## 3. Repository layout, build, and tooling

This part fixes the on-disk shape of `Finger Lickin Music/`, the HTML shell that every
module is concatenated into, the four Node tools, the optional relay server, the two
development ledgers, the developer loop, and the source style. Everything here is normative:
the implementing session creates these files with these names and these contents. Nothing
in this part exists yet at plan version 1.0.0.

Rules that follow from the tree:

- The shipped build contains `shell.html` plus every `src/NN-name.js` whose two-digit prefix is
  01-30, in file-name order. Every file whose name matches `^9\d-` is excluded from the
  shipped build and included in the test build (section 3.3). The runner `90-selftest.js` is
  therefore absent from `FingerLickinMusic.html`; in that file `FLM.selfTest` is `undefined`
  and `FLM.selfTestReady` is `false` (set by M-29).
- One unit-test file per module, named `91-test-<module>.js` where `<module>` is the file's
  own suffix (`05-audio.js` -> `91-test-audio.js`). The test group name equals that suffix.
  The five cross-module groups live in `92-test-<group>.js` with group names `integration`,
  `timing`, `files`, `faults`, `perf-smoke`. These 36 group names are the complete list the
  runner knows (Part 6, M-31).
- No file is ever added outside this tree without a LEDGER entry naming it. Splitting a module
  into several files (as `ClassTimeKiller/src/07a-render.js` does) is allowed only with the
  form `NNx-name-part.js` (`18a-render-math.js`, `18b-render-gl.js`); all parts of one module
  still attach to one namespace, and the test file stays `91-test-render.js`.
- `test-corpus/` files are regenerated only by `tools/make-corpus.mjs`; hand edits are not
  allowed (section 3.6 makes `--check` fail on any difference).
- The repository root `.gitignore` gets the two lines in section 3.10.

### 3.2 `src/shell.html` specification

`shell.html` is the only HTML file. It holds the head, the complete stylesheet, the DOM
scaffold, a tiny early error handler, and one `<script>` containing the `/*@@SCRIPT@@*/`
marker. It contains no other script, no external reference of any kind, and no text that is
not ASCII. The build (3.3) replaces the marker and nothing else.

Decisions behind the head:

- The CSP is ADR-12 verbatim. The Online edition build appends the relay origin to
  `connect-src` (3.3.6); nothing else in the head differs between editions.
- `rel="icon" href="data:,"` suppresses the favicon request that would otherwise fail under
  `file://`. No `apple-touch-icon` is declared: iOS then uses a screenshot, which is acceptable
  and avoids an embedded image.
- `maximum-scale=1, user-scalable=no` is required so a double tap on a touch pad never zooms;
  UI scaling is provided by the `--ui` token instead (3.2.2), which keeps B 22 "scalable UI".
- `color-scheme: dark` makes form controls and scrollbars match the dark palette; there is no
  light theme in v1.

Semantics the whole UI must respect (P 2.1, P 2.3):

| Token group | Used for | Never used for |
|---|---|---|
| `--c-accent` | the one primary action per screen, the selected item, the active tab, the Record button when armed | body text, borders of ordinary panels, decorative fills |
| `--c-accent-2` | informational emphasis, links, the "synthesized" fidelity badge, metronome indicator | success or error meaning |
| `--c-ok / --c-warn / --c-error` | status text, compatibility badges (Supported, Partial or Conversion, Unsupported), save state, connection state | lane or judgment coloring |
| `--lane-N` | highway lanes, touch pads, dance arrows, chart previews, Free Play key labels | any UI status |
| `--j-*` | judgment text and flashes in the HUD | anything outside the HUD |
| `--c-text-muted` | labels, units, secondary lines | the only carrier of required information |

Typography rules: headings use `--fs-5` or `--fs-4` with `--fw-bold` and `--lh-tight`; body and
buttons `--fs-3` `--fw-medium`; labels `--fs-2` `--c-text-muted`; every number that changes
during play (score, combo, time, BPM, latency) is set in `font-variant-numeric: tabular-nums`
so digits do not jitter; the judgment word uses `--fs-6` `--fw-bold`. Nothing uses a size
outside the six tokens.

Motion rules: panel open and close use `--t-base`; pressed feedback `--t-fast`; screen
transitions `--t-slow`; the highway, the 3D stage and the metronome indicator are not CSS
animations and are governed by the reduced-motion setting in JS (M-21 and M-26 read
`document.documentElement.classList.contains('reduced-motion')`): reduced motion disables
camera motion, particles, judgment pop scaling, and panel slides; it never disables the
highway scroll, the hit flash, or the beat indicator, which are gameplay information.

#### 3.2.3 Body and html classes

| Class | Element | Set by | Meaning |
|---|---|---|---|
| `reduced-motion` | `html` | M-26 at boot and on `settings.changed` | effective reduced motion (setting `video.reducedMotion` is `system`, `on`, or `off`; `system` follows the media query) |
| `motion-full` | `html` | M-26 | setting is `off`: full motion even when the OS asks for reduced motion |
| `high-contrast` | `html` | M-26 | setting `video.highContrast` is true |
| `portrait` or `landscape` | `body` | M-26 on `resize` and `orientationchange`, from `innerWidth < innerHeight` | exactly one is present at all times |
| `compact` | `body` | M-26 | `min(innerWidth, innerHeight) < 600` CSS px (phone-sized) |
| `touch` | `body` | M-29 at boot from `navigator.maxTouchPoints > 0` | touch pads are offered; hover styles are disabled |
| `in-game` | `body` | M-28 on `mode.enter` for `quickplay`, `instrument`, `dance`, `multiplayer` (while playing) | hides the cursor over the canvas after 2 s idle; blocks text selection |

Layering is fixed by the `--z-*` tokens: the canvas (view or flat) at the bottom, screens and
dialogs in `#overlay`, HUD above them (so a pause dialog never hides the score), touch pads
above the HUD, toasts, the rotate recommendation, and `#fatal` on top of everything.
`#overlay`, `#hud` and `#touch` are `pointer-events: none` containers whose children opt in;
this is what lets pointer events reach `canvas#view` where nothing else is drawn (M-07 attaches
the gameplay pointer listeners to `#touch > .pad` elements and to `#view`).

### 3.3 `tools/build.mjs`

Zero-dependency ES module run with Node 22 or newer. It is the only way the HTML files are
produced; players never run it (ADR-01).

#### 3.3.1 Command line

```text
node tools/build.mjs [--check] [--online <relayUrl>] [--quiet]
```

| Flag | Effect |
|---|---|
| (none) | builds `FingerLickinMusic.html` (shipped) and `FingerLickinMusic.test.html` (test) next to `src/` |
| `--check` | runs every step including all checks and the size gate, writes nothing, prints the report |
| `--online <relayUrl>` | additionally builds `FingerLickinMusic.online.html`: same as the shipped file with `connect-src` widened to the relay origin and `RELAY_URL` set (3.3.6); `<relayUrl>` must parse as a URL with scheme `ws:` or `wss:`, else exit 2 |
| `--quiet` | prints only problems and the final line |

Paths are resolved from the script's own location (`dirname(fileURLToPath(import.meta.url))/..`),
so the command works from any current directory.

#### 3.3.2 Inputs and ordering

1. `src/shell.html` (required; missing -> exit 3).
2. Every `src/*.js`, sorted by file name with `localeCompare(b, 'en', { numeric: false })`
   on the raw name (plain code-point order; names are ASCII lower case so this equals byte
   order). A file name must match `/^\d\d[a-z]?-[a-z0-9-]+\.js$/`, else problem
   `bad file name`.
3. Shipped set = files whose name does not match `/^9\d/`. Test set = all files.
4. Every file's text is decoded as UTF-8, a leading U+FEFF is stripped, `\r\n` and lone `\r`
   become `\n`, a missing final newline is added. Any byte >= 0x80 in a `.js` file is a
   problem `non-ASCII byte in <file>:<line>` (ADR-09 keeps source ASCII; user-facing text with
   accents is not needed in v1). The shell may contain only ASCII too.

#### 3.3.3 Joining

```text
header   = '/* Finger Lickin Music ' + VERSION + ' built ' + isoDate + ' ' + edition + ' ' + kind + ' */\n'
             edition in {standalone, online}; kind in {ship, test}
body     = for each file in set: '// ==== ' + file.name + ' ====\n' + file.text (after token replacement) + '\n'
script   = header + body
page     = BOM + shell.replace('/*@@SCRIPT@@*/', script)       (first occurrence only; shell must contain exactly one)
```

No other transformation is applied: comments are kept, indentation is kept, nothing is
minified (B 19.4). The shipped size budget in section 6 of the brief is sized for untouched
source.

Token replacement happens only in `src/01-core.js`:

| Token (exact text in source) | Replaced by |
|---|---|
| `'@@BUILD@@'` | `'<isoDateTime> <edition> <kind>'`, for example `'2026-11-02T10:14:00Z standalone ship'` |
| `'@@RELAY_URL@@'` | `'<relayUrl>'` for the online build, `''` otherwise |

`01-core.js` declares them as `const VERSION = '0.1.0';`, `const BUILD = '@@BUILD@@';`,
`const RELAY_URL = '@@RELAY_URL@@';` and exposes them as `FLM.Core.VERSION`, `FLM.Core.BUILD`,
`FLM.Core.RELAY_URL` (M-29 mirrors `VERSION` to `window.FLM.VERSION`). The build reads `VERSION`
with `/^const VERSION = '(\d+\.\d+\.\d+(?:-[0-9A-Za-z.]+)?)';$/m`; no match is a problem.
The software version starts at `0.1.0` and is set to `1.0.0` in Phase 16; it is independent
of the plan version.

#### 3.3.4 Checks (every one is a `problem`; any problem -> no files written, exit 1)

| Check | Rule |
|---|---|
| marker | the shell contains the marker exactly once |
| skeleton | each module file's first non-comment, non-blank line is `(function () {` and its last non-blank line is `})();` (3.11) |
| strict | each module file contains the line `'use strict';` as its second non-comment line |
| namespace | each `NN-name.js` with NN in 01-30 contains exactly one `FLM.Core.define('<Namespace>',` call (01-core.js instead contains `window.FLM = `) and the namespace matches the module table in the brief; each `91-test-*.js` contains exactly one `FLM.SelfTest.group('<name>',` whose name equals the file suffix |
| top-level names | no `const`, `let`, `var`, `function`, `class` declaration at column 0 outside the IIFE in any file (there must be none; the IIFE wraps everything) |
| banned APIs | anywhere: `fetch(`, `XMLHttpRequest`, `import(`, `importScripts`, `navigator.sendBeacon`, `eval(`, `new Function(`, `document.write`, `.innerHTML`, `.outerHTML`, `insertAdjacentHTML`, `setTimeout('`, `setInterval('`. Allowed only in `24-net.js`: `new WebSocket`, `RTCPeerConnection`. Allowed only in `01-core.js` and `90-selftest.js`: an assignment to a `window.` property (`window.FLM`, `window.__FLM_RESULTS`). Comment text is ignored by stripping `//` to end of line before matching (strings are not stripped, so string literals containing these names also fail: write them differently) |
| syntax ceiling | banned tokens (ES2021 and later): `??=`, `` \|\|= ``, `&&=`, private fields (`/^\s*#\w+/m` or `this\.#`), `static {`, and `import ` or `export ` at line start; numeric separators are not checked |
| non-ASCII | 3.3.2 item 4 |
| duplicate blocks | 8 consecutive meaningful lines (>= 12 chars, not starting with `{`, `[`, quote, or comment) appearing twice across the shipped set -> problem `DRY: duplicated block at <file>:<line> (same as <file>:<line>)`; data files `30-content.js`, `06-instruments.js`, `02-theory.js` are exempt |
| parse | the joined test script and the joined shipped script each pass `node --check` (3.3.5) |
| size | shipped page > 2,621,440 bytes (2.5 MB) -> problem; > 1,572,864 bytes (1.5 MB) -> warning line, not a problem; the test page is reported but not gated |

#### 3.3.5 `node --check`

The joined script is written to `join(os.tmpdir(), 'flm-build-' + process.pid + '-' + kind + '.js')`
and `spawnSync(process.execPath, ['--check', tmpPath], { encoding: 'utf8' })` is run; a
non-zero status adds the problem `the joined <kind> script does not parse: <stderr first 3
lines>`; the temp file is deleted in a `finally`. This is run for both the shipped and the
test script because a test file can break the test build alone.

#### 3.3.6 Online edition

With `--online <relayUrl>`: `origin = new URL(relayUrl).origin` (for `ws:` and `wss:` URLs this is
`ws://host:port` or `wss://host`), the CSP string `connect-src 'self'` becomes
`connect-src 'self' <origin>`, the `RELAY_URL` token gets the full URL, `edition = online`, and
the page is written to `FingerLickinMusic.online.html`. The online file is not committed
(3.10): it embeds an operator-specific URL. A test variant of the online edition is not
produced; relay integration tests use `--file` on `tools/selftest.mjs` against this file with
the group `net` after a `--online ws://127.0.0.1:8787` build (Part 12).

#### 3.3.7 Outputs, report, exit codes

Outputs (written atomically: write `<name>.tmp` then `renameSync` over the target):
`Finger Lickin Music/FingerLickinMusic.html`, `Finger Lickin Music/FingerLickinMusic.test.html`,
and with `--online` also `Finger Lickin Music/FingerLickinMusic.online.html`. Each begins with
one UTF-8 BOM, uses LF only, and ends with `</html>\n`.

Report lines (stdout): `files <n> (ship <m>, test <k>)`, `version <VERSION> build <BUILD>`,
`size ship <x.xx> MB, test <y.yy> MB`, one `  WARNING ...` line when over 1.5 MB, one line per
problem, then `BUILD OK -> FingerLickinMusic.html, FingerLickinMusic.test.html` or `CHECK OK`
or `BUILD FAILED: <n> problem(s)`.

| Exit code | Meaning |
|---|---|
| 0 | all checks passed; files written (or `--check`) |
| 1 | at least one problem (nothing written) |
| 2 | usage error (unknown flag, missing or invalid `--online` URL) |
| 3 | I/O error (missing `src/shell.html`, unreadable file, write failure) |

#### 3.3.8 Pseudocode

```js
// tools/build.mjs (structure; the implementation follows these names)
const ROOT = join(dirname(fileURLToPath(import.meta.url)), '..');
const args = parseArgs(process.argv.slice(2));            // {check, online, quiet} or exit 2
const problems = [];
const shell = readText(join(ROOT, 'src', 'shell.html'));  // strips BOM, normalizes LF; exit 3 on failure
const files = listSources(join(ROOT, 'src'));              // sorted; validates names; reads and normalizes
const version = readVersion(files.find(f => f.name === '01-core.js'));
checkShell(shell); files.forEach(checkFile);               // marker, skeleton, strict, namespace, banned, ascii
checkDuplicates(files.filter(isShipped));
const ship = joinPage(shell, files.filter(isShipped), { edition: 'standalone', kind: 'ship', relayUrl: '' });
const test = joinPage(shell, files, { edition: 'standalone', kind: 'test', relayUrl: '' });
const online = args.online ? joinPage(shellWithCsp(shell, originOf(args.online)), files.filter(isShipped),
                                      { edition: 'online', kind: 'ship', relayUrl: args.online }) : null;
checkParse(ship.script, 'ship'); checkParse(test.script, 'test');
checkSize(ship.bytes);
report();
if (problems.length) exit(1);
if (!args.check) { writeAtomic(OUT_SHIP, ship.page); writeAtomic(OUT_TEST, test.page); if (online) writeAtomic(OUT_ONLINE, online.page); }
exit(0);

function joinPage(shell, set, opts) {
  const header = `/* Finger Lickin Music ${version} built ${opts.date} ${opts.edition} ${opts.kind} */\n`;
  const body = set.map(f => `// ==== ${f.name} ====\n${replaceTokens(f, opts)}\n`).join('');
  const script = header + body;
  const page = String.fromCharCode(0xFEFF) + shell.replace(MARK, () => script);   // one BOM; function form: no $-pattern expansion
  return { script, page, bytes: Buffer.byteLength(page, 'utf8') };
}
```

### 3.4 `tools/selftest.mjs`

Drives the in-page runner (M-31) headlessly. Zero npm installs: it loads the preinstalled
Playwright through `createRequire(import.meta.url)('playwright')`.

#### 3.4.1 Command line

```text
node tools/selftest.mjs [--group <name>]... [--all] [--grep <substring>] [--slow] [--headed]
```

| Option | Default | Meaning |
|---|---|---|
| `--group <name>` | (none) | run this group; may repeat; unknown name -> the runner reports zero tests and the tool fails with the known group list |
| `--all` | implied when no `--group` | run every group |
| `--grep <substring>` | (none) | only tests whose `group/name` contains the substring (case-insensitive) |
| `--slow` | off | also run tests registered with `{ slow: true }` (10 min loops, drift, long sessions); raises the watchdog to 900 s |
| `--headed` | off | launch with `headless: false` for watching a run |
| `--json <path>` | (none) | write the full results object (3.4.4) to this path |
| `--file <html>` | `FingerLickinMusic.test.html` | the page to open |

| `--timeout <s>` | 240 (900 with `--slow`) | whole-run watchdog |

#### 3.4.2 Launch

```js
const FLAGS = ['--autoplay-policy=no-user-gesture-required', '--use-gl=angle', '--use-angle=swiftshader',
               '--enable-unsafe-swiftshader', '--enable-precise-memory-info'];
async function launch(headed) {
  const { chromium } = require('playwright');                       // createRequire; throws -> exit 3 with hint
  const options = { headless: !headed, args: FLAGS };

    try { return await chromium.launch({ ...options, executablePath: fallback }); }
    catch (second) { throw new Error('cannot launch Chromium: ' + first.message + ' / ' + second.message); }
  }

```

Context: `browser.newContext({ viewport: { width: 1280, height: 720 }, deviceScaleFactor: 1,
hasTouch: false })`. A second context with `hasTouch: true, viewport 390 x 844` is opened only
when a selected group is `input`, `ui`, `integration` or `faults`, and those groups' touch
tests run there (the runner receives `{ touch: true }` in options). Page events recorded:
`pageerror` (message and stack), `console` with type `error`, `crash` (fail immediately,
exit 1), `dialog` (auto-dismiss, record as failure: the game must not call `alert`).

#### 3.4.3 Run sequence

1. Resolve `--file`; if it does not exist print `missing <path>: run node tools/build.mjs first`
   and exit 3.
2. Start the watchdog: on expiry print `TIMEOUT after <s> s`, close the browser, exit 2.
3. `page.goto('file://' + absolutePath + '?test')`. The `?test` parameter tells M-29 to boot
   without the first-launch flow and without the audio unlock gate (Part 6, M-29).
4. `page.waitForFunction(() => window.FLM && window.FLM.selfTestReady === true, null, { timeout: 30000 })`;
   on timeout, print the collected page errors and exit 1 (the build booted but the runner never
   became ready: a module load error).
4a. When the selection includes `files`, `integration` or `faults` (or is `--all`), the tool
   reads `test-corpus/MANIFEST.json` and every file it lists, and injects them:
   `await page.evaluate((entries) => window.FLM.SelfTest.corpus.load(entries), entries)` with
   `entries = [{ file, bytes, fnv1a32, recipe, format, expect, base64 }]`. `fetch` is banned
   and `file://` pages cannot read sibling files, so the tool is the only corpus source; a
   manual run from the Diagnostics screen skips corpus tests with the message
   `corpus not loaded (run tools/selftest.mjs)`. The runner decodes base64 to `Uint8Array`
   once and verifies each `fnv1a32` before any test runs (mismatch fails the group).
5. `const results = await page.evaluate(([groups, opts]) => window.FLM.selfTest(groups, opts), [groups, { slow, grep, touch: false }])`
   where `groups` is `undefined` for all, else the array of names. `FLM.selfTest` returns a
   Promise resolving to the results object and also assigns it to `window.__FLM_RESULTS`.
   The tool reads `window.__FLM_RESULTS` after the promise resolves and uses that object (the
   two are the same reference; reading the global is what the ADR-11 contract specifies and
   what a manual run in the Diagnostics screen produces).
6. If a touch context is needed, repeat steps 3-5 there with `{ touch: true }` and only the
   touch-capable groups; merge results with group names suffixed `@touch`.
7. Print the table and summary; write `--json`; exit per 3.4.6.

| Code | When |
|---|---|
| 0 | every selected test passed, no page errors, at least one test ran (or `--smoke` passed) |

| 2 | watchdog timeout |

fails individually and the run continues; only a hung runner trips the watchdog.

`headless-gated`.

### 3.6 `tools/make-corpus.mjs`

Writes `test-corpus/` deterministically. The file list, recipes and expected results are
specified in Part 8.9; this section fixes the generator's structure and its determinism
contract. The generator must not import anything from `src/`: the corpus is the oracle the
game's parsers are tested against, so it is produced by independent, deliberately simple
writers.

```text
node tools/make-corpus.mjs [--out <dir>] [--check] [--only <file-glob>] [--list]
```

| Option | Meaning |
|---|---|
| `--out <dir>` | output directory (default `test-corpus/` next to `src/`) |
| `--check` | generate to memory and compare byte-for-byte with the files on disk; print `OK` or each differing file; exit 1 on any difference or missing file (this is the gate that the checked-in corpus is reproducible) |
| `--only <glob>` | restrict to matching file names (simple `*` glob) |
| `--list` | print the recipe table (file, format, seed, byte count) without writing |

#### 3.6.1 Structure

```js
// tools/make-corpus.mjs (structure)
const RECIPES = [ /* one entry per Part 8.9 row: */
  { file: 'midi-mono-simple.mid', format: 'midi', seed: 1001, make: (rng) => smf(...), expect: { tracks: 1, notes: 32, warnings: [] } },
  { file: 'midi-mono-simple.trunc-120.mid', format: 'midi', seed: 1001, base: 'midi-mono-simple.mid', mutate: [['truncate', 120]],
    expect: { error: null, warnings: ['W-MIDI-TRUNCATED'] } },
  /* ... */
];
// writers (all self-contained, all synchronous, all operating on Uint8Array or string):
//   Prng(seed)            mulberry32; next(), int(lo, hi), pick(array) - the same algorithm as FLM.Core.Prng
//   SmfWriter             header(format, ntrks, division), track(events) with VLQ deltas, meta, running status on or off
//   musicXml(template, vars)   partwise and timewise string templates, divisions, attributes, notes, chords, ties,
//                              tuplets, repeats, endings, transpose, dynamics, articulations, lyrics
//   zipStored(entries)    local headers + central directory + EOCD, method 0 only, CRC32 table; used for .mxl
//   Gp5Writer             version string, info strings, lyrics, page setup, tempo, key, octave, 64 channels,
//                         measure headers, track headers (tuning, capo, port/channel), beats, notes, effects
//                         (bend points, slide, hammer, palm mute, harmonic, dead, tied, let ring, grace)
//   Gp3Writer, Gp4Writer  the same arrangement in the older layouts (fewer fields) for the version tests
//   mutate(bytes, ops)    truncate(n) | setByte(off, v) | xorRange(off, len, mask) | insert(off, bytes) |
//                         patchU32BE(off, v) | patchU16BE(off, v) | repeat(off, len, times)
//   fnv1a32(bytes)        the same function as FLM.Core.fnv1a32 (hex, 8 chars)
main(): for each recipe in file-name order -> bytes = recipe.base ? mutate(cache[base], recipe.mutate) : recipe.make(new Prng(recipe.seed))
        -> compare with disk -> write when different (unless --check) -> manifest row
        -> write MANIFEST.json (sorted by file, 2-space JSON, LF, trailing newline)
        -> print `wrote <n>, unchanged <m>, total <bytes> bytes`
```

#### 3.6.2 Determinism contract

- No `Date`, no `Math.random`, no environment-dependent values, no object-key iteration where
  order could differ (arrays only). Every recipe has a fixed `seed`; the seed table is part of
  Part 8.9 and never changes once a file is committed (a change is a new file name).
- Output bytes depend only on the recipe table and the writer code. `--check` is run in the
  developer loop (3.9) and by the Phase 15 gate; any difference is a defect.
- Text outputs (`.musicxml`, `.xml`, `container.xml`) are ASCII, LF, no BOM; binary outputs are
  written exactly as produced. File names are lower-case ASCII with hyphens and dots only.
- Mutated variants are derived from the base recipe's bytes in memory, so a base change changes
  its variants consistently.
- `MANIFEST.json` rows: `{ "file", "bytes", "fnv1a32", "format", "recipe", "base", "mutate", "expect" }`
  where `expect` is the Part 8.9 expectation (tracks, note count, warning codes, or an error
  code). Expectations are authored in the recipe, never computed by running the game's parsers.
- Size policy: no corpus file exceeds 2 MB; the import-limit rejections (file > 25 MB, events
  > 1,000,000, tracks > 128) are tested with buffers constructed in memory by `92-test-files.js`
  (a header claiming huge counts over a short body is a committed corpus file; a genuinely huge
  file is not).
- Writers are tested by the corpus itself: each base file is also parsed by the game in the
  `files` group; a writer bug shows up as an unexpected warning against the authored `expect`.

### 3.7 `server/relay.mjs`

Optional relay for the Online edition (ADR-07). Node 22 or newer, zero dependencies, hand-written
RFC 6455 WebSocket over `http`'s `upgrade` event. It relays opaque text payloads between the
members of a room and knows nothing about the game except room membership.

#### 3.7.1 Running

```text
PORT=8787 HOST=0.0.0.0 node server/relay.mjs
node server/relay.mjs --selftest        # in-process client exercises handshake, framing, rooms, limits; exit 0 or 1
```

| Environment variable | Default | Meaning |
|---|---|---|
| `PORT` | `8787` | TCP port |
| `HOST` | `0.0.0.0` | bind address |
| `MAX_ROOMS` | `200` | create fails with `SERVER_FULL` above this |
| `LOG_LEVEL` | `info` | `silent`, `error`, `warn`, `info`, `debug` |

TLS: the relay speaks plain `http`/`ws`. For `wss://` run it behind a reverse proxy that
terminates TLS and forwards the upgrade (nginx: `proxy_http_version 1.1; proxy_set_header
Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_read_timeout 120s;`).
Browsers require `wss://` when the game page itself is served over `https://`; a `file://` page
may use `ws://`. The client build must name the final public URL (`--online wss://relay.example.org/`).

#### 3.7.2 HTTP and handshake

- `GET /health` -> `200 application/json` `{"ok":true,"rooms":<n>,"connections":<n>}`.
- Any other plain request -> `404` with an empty body. No static files, no credentials, no cookies.
- `upgrade` event: require `Upgrade: websocket` (case-insensitive), `Connection` containing
  `upgrade`, `Sec-WebSocket-Version: 13`, a `Sec-WebSocket-Key`. Else respond `400` and destroy
  the socket. Accept value: `base64(sha1(key + '258EAFA5-E914-47DA-95CA-C5AB0DC85B11'))`. Reply
  `HTTP/1.1 101 Switching Protocols` with `Upgrade: websocket`, `Connection: Upgrade`,
  `Sec-WebSocket-Accept`. No subprotocol, no extensions (`permessage-deflate` is not negotiated;
  the client never requests it).
- Origin is not checked: the client is a publicly distributed file and may be opened from
  `file://` (no Origin) or any host (B 23.4).

#### 3.7.3 Framing

| Rule | Behavior |
|---|---|
| Client frames | must be masked; an unmasked frame -> close 1002 |
| Opcodes | 1 text: accepted; 0 continuation: buffered until FIN; 2 binary: close 1003; 8 close: echo close and end; 9 ping: reply pong with the same payload; 10 pong: clears the pending-ping flag; others: close 1002 |
| Length forms | 7-bit, 16-bit, 64-bit (high 32 bits must be 0) |
| Message cap | a message (all fragments) above 65,536 bytes -> close 1009 |
| UTF-8 | payload must decode as valid UTF-8 (`new TextDecoder('utf-8', { fatal: true })`); failure -> close 1007 |
| Server frames | unmasked, text only, each message one frame |
| Keepalive | server pings every 30 s; no pong within 30 s -> destroy the socket (counts as leave) |
| Backpressure | if `socket.writableLength` exceeds 1 MB the connection is closed with 1008 (a stalled client cannot grow memory) |

#### 3.7.4 Rooms and relay protocol

Room codes are 6 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (32 symbols; no I, O, 0, 1)
drawn with `crypto.randomInt`, unique among live rooms. Member ids are small integers assigned
per room starting at 1; id 1 is the creator (host).

Relay envelope (JSON text frames; distinct from the game's `NetMessage`, which travels inside
`data` as a string the relay never parses):

| Direction | Frame | Rules |
|---|---|---|
| client -> relay | `{"op":"create"}` | one room per connection; reply `{"op":"created","code":"ABC234","id":1}`; `SERVER_FULL` at `MAX_ROOMS` |
| client -> relay | `{"op":"join","code":"ABC234"}` | code upper-cased and validated against the alphabet (`BAD_CODE`), room must exist (`ROOM_NOT_FOUND`), fewer than 4 members (`ROOM_FULL`), connection not already in a room (`ALREADY_IN_ROOM`); reply `{"op":"joined","code":"ABC234","id":3,"peers":[1,2]}`; other members get `{"op":"peer","id":3,"event":"join"}` |
| client -> relay | `{"op":"msg","to":0,"data":"<string>"}` | `to` 0 = every other member, else a member id (`NO_SUCH_PEER`); sender must be in a room (`NOT_IN_ROOM`); `data` must be a string (`BAD_FRAME`); delivered as `{"op":"msg","from":<id>,"data":"<string>"}` unchanged |
| client -> relay | `{"op":"leave"}` | removes the member; others get `{"op":"peer","id":<id>,"event":"leave"}`; a socket close is an implicit leave |
| relay -> clients | `{"op":"closed","reason":"host-left" or "expired" or "shutdown"}` | sent to the remaining members when the host (id 1) leaves, when the room idles out, or on `SIGTERM`; the room is deleted and the sockets are closed with 1001 |
| relay -> client | `{"op":"error","code":"<CODE>","message":"<short ASCII text>"}` | codes: `BAD_FRAME`, `BAD_CODE`, `ROOM_NOT_FOUND`, `ROOM_FULL`, `ALREADY_IN_ROOM`, `NOT_IN_ROOM`, `NO_SUCH_PEER`, `RATE_LIMIT`, `TOO_LARGE`, `SERVER_FULL` |

Limits: 4 members per room; 64 KB per message (3.7.3); 60 messages per second per connection
(token bucket, capacity 60, refill 60 per second; an exceeding frame is dropped and answered
with `RATE_LIMIT`; the fourth `RATE_LIMIT` within 10 s closes the connection with 1008); a
connection that sends anything other than `create` or `join` before being in a room gets
`NOT_IN_ROOM`; unparseable JSON or an unknown `op` gets `BAD_FRAME` and the third `BAD_FRAME`
on one connection closes it with 1008. Room idle expiry: 10 minutes without any frame from any
member (checked every 30 s). No late join after the game starts is enforced by the host (M-24),
not by the relay, because the relay does not know the game state.

#### 3.7.5 What the relay never does

- It never stores anything: rooms live in a `Map` in memory; a restart drops every room and
  clients receive the socket close (E 8.1 "server restarts" -> the client shows `DLG-NetError`
  and the game continues in standalone mode).
- It never interprets `data`, never validates game payloads, never computes scores: the host
  client is authoritative (ADR-07, E 8.3). The only client-visible server decisions are room
  membership and the limits above.
- It has no credentials, no admin endpoint, no configuration file, no persistence, no
  dependency, and no outbound connection.
- Logging (`LOG_LEVEL`): `info` prints startup (`relay listening on <host>:<port>`), room count
  changes (`rooms <n>`), and shutdown; `warn` prints limit violations by error code and a
  per-process connection counter (no address); `debug` prints frame opcodes and lengths (never
  payloads, never room codes). No IP address, user agent, room code or payload is ever logged
  at any level (B 23.2).

#### 3.7.6 `--selftest`

Starts the server on an ephemeral port, connects three raw `net` sockets using the same framing
code as clients (the file exports nothing; the self-test is a function inside it), and asserts:
handshake accept value for the RFC 6455 example key (`dGhlIHNhbXBsZSBub25jZQ==` ->
`s3pPLMBiTxaQ9kYGzzhZRbK+xOo=`), masked text round trip in all three length forms, fragmentation,
ping/pong, close echo, `create` and `join` happy path, `ROOM_FULL` on the fifth join, `BAD_CODE`,
`ROOM_NOT_FOUND`, `msg` fan-out and unicast, `TOO_LARGE` close 1009 at 65,537 bytes, `RATE_LIMIT`
after 61 frames in one second, `host-left` closing, and idle expiry with the timer shortened by
the `--selftest` flag to 2 s. Prints `RELAY SELFTEST <passed>/<total>` and exits 0 or 1. Part 12
lists this as an IT entry.

### 3.11 Source style and module skeleton

ADR-09 rules, made concrete:

- UTF-8 with BOM, LF, ASCII-only content (the build fails on any byte >= 0x80); 2-space indent;
  single quotes; semicolons on every statement; `const` and `let` only (no `var` outside the
  shell's early script); `===` only; maximum line length 120.
- ES2020 ceiling: optional chaining, nullish coalescing, `BigInt`, `Promise.allSettled`,
  `globalThis` allowed; no logical assignment, no private class fields, no static blocks, no
  top-level `await`, no `import`/`export` in `src/`. Classes are allowed. Async functions and
  Promises are allowed; the hot paths (scheduler tick, render loop, judge) stay synchronous.
- Exactly one IIFE per file; the IIFE's first statement is `'use strict';`. Nothing is declared
  outside it. The only global writes in the code base are `window.FLM` (01-core.js) and
  `window.__FLM_RESULTS` (90-selftest.js); the shell's early script owns `window.__flmEarlyErrors`
  until M-01 deletes it.
- Every module registers through `FLM.Core.define(name, factory)` and returns a frozen
  namespace object. `define` throws on a duplicate name, calls the factory immediately, assigns
  `FLM[name]`, records `{ name, file, order }` in `FLM.Core.modules`, and if the factory throws
  it reports `E-GEN-001` (`context.module`) through `ErrorReporter`, a `reload`-class failure at boot (a module that
  fails to load is fatal) and rethrows so the early handler shows `#fatal`.
- Naming: `camelCase` functions and variables, `PascalCase` classes and types, `UPPER_SNAKE`
  module-level constants, event topics lower-case dotted (`transport.state`), error codes
  `E-XXX-nnn`, warning codes `W-XXX-NAME`. Time variables carry their domain: `tick` (integer
  ticks), `tAudio` (seconds, audio clock), `tPerf` (milliseconds, `performance.now()`), `ms`
  suffix for millisecond durations, `sec` suffix for second durations.
- DOM: created through `FLM.UI.el(tag, attrs, children)` and `textContent`; `innerHTML` and
  friends are banned by the build. Every listener added by a module is registered through
  `FLM.Core.dom.on(target, type, handler, options, owner)` which returns a disposer and counts, so
  `FLM.Modes.assertClean()` can prove the listener delta is zero (Part 4.7).
- Timers: `setTimeout`, `setInterval` and `requestAnimationFrame` are called through
  `FLM.Core.timers` wrappers for the same reason; raw calls are allowed only inside
  `01-core.js`.
- Comments: one header line per file naming the module and its one-line responsibility; JSDoc
  on every public function (params, return, thrown errors, emitted events); inline comments
  explain intent, not syntax. Spec references in comments use the brief's form (`B 9.2`).
- Numbers: ticks and scores are integers; use `Math.round` and `Number.isInteger` assertions
  (`FLM.Core.assert`) at module boundaries rather than bitwise truncation.
- No `console.log` in `src/` outside `01-core.js` (`Log` wraps it; the build does not ban it, the
  code review at each phase gate does).
