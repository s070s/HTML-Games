# Input (S05) and UI shell (S18) - public API

Files: `05a-input.js` (action table, bindings, keyboard + mouse, latch, aim assist, pointer lock, pause rules), `05b-input-touch.js` (touch controls, layout editor model, gyro), `05c-input-gamepad.js` (gamepad), `18a-ui.js` (screen stack, focus navigation, toasts, control builders), `18b-ui-menus.js` (screens), `18c-ui-perf.js` (performance overlay), `18p-ui-device.js` (phone and Home Screen helpers), `18q-ui-rotate.js` (rotate guard). Tests: groups `input` and `ui`.

## What the input layer writes (every frame, Loop `input` phase)

For the local player (`Game.playerId`), only while `Game.isRunning()` (playing and not paused), before the sim steps:

| Field | Value |
|---|---|
| `Actors.moveX` / `moveZ` | -1..1, +1 = strafe right / forward; keyboard + touch stick + pad stick summed, length clamped to 1 |
| `Actors.aimYaw` / `aimPitch` | desired view angles in radians. Yaw increases to the LEFT (DATA-002), so looking right lowers it. Pitch clamped to +-89 deg. The systems copy these into `yaw`/`pitch` |
| `Actors.buttons` | `BTN` bits: held actions plus latched presses (below) |
| `Actors.slotRequest` | 1-9 for one sim step after a slot key, else 0 |

`Input.aim` `{ yaw, pitch }` holds the same angles at full precision, updated every frame before the sim steps: the renderer may use it for the local player's camera so look latency stays under one frame even when no sim step runs that frame (INP latency check). `Input.setAim(yaw, pitch)` turns it from the sim (S08 teleporter exits for `Game.playerId`, MOV-019).

View angles resynchronise from `Actors.yaw/pitch` whenever `Actors.spawnCount[id]` changes (a mode that respawns the player must set `Actors.yaw/pitch` and bump `spawnCount`).

### Latch and buffer (INP-009)

- A press is kept in `buttons` until a sim step has consumed it (`Sim.tick` changed), so a tap shorter than a frame is never lost. A second tap right after a first one waits (at most 0.10 s) for a step that sees the bit low, so every tap makes its own `Actors.pressed` edge.
- `Input.buffered(actionId)` is true when the action was pressed within 0.10 s of **sim time** (12 ticks); `Input.consumeBuffered(actionId)` clears it. Move (jump before landing) and Weapons (fire during a cooldown) call these for the 0.10 s buffer. Only rows with `buffered: true` (`jump`, `fire`) keep a press time; `buffered()` is false for every other action. Press times are cleared by `Input.clearAll()` (new match, pause, rebinding), so a press never outlives a restart.
- Wheel notches are queued: one weapon switch per notch even when several arrive in one frame.

## Action table

`Input.actions` (= `ACTION_ROWS`) is the single table. Row: `{ id, label, group, button | axis+sign | slot | event, toggle?, padToggle?, buffered?, always?, kbm: [binding, binding], pad: binding }`.

- `button`: `BTN` bit written to `Actors.buttons`. `axis`/`sign`: digital move key. `slot`: weapon slot request. `event`: no sim effect; emits `input.action`.
- `toggle: true` rows (crouch, sprint, walk, prone, fire, alt, use, scoreboard) have a setting `controls.toggle.<id>` = `hold` | `toggle` (INP-002). `padToggle: true` (sprint) adds `controls.toggle.sprintPad` ("Sprint on a controller", default `toggle`, because L3 is held while steering): a controller press follows it alone, a keyboard press follows `controls.toggle.sprint`. L3 sprint toggles only where sprint is a run; `Input.padToggleRule(actionId)` (filled by S10 `10a-move.js`) answers 0 = hold (the player's preset has `sprintSpeed` 0: sprint is a dash, charge or walk, as in Ravager, Knight, Tactical, so each click is a new press), 1 = toggle, 2 = toggle where the preset has a tactical sprint (Modern): a click while the sprint is on counts as a new press (the tactical sprint's second tap), not as off. A toggled sprint ends by itself when the run ends (a stop, a shot, no stamina: `Input.resetToggle('sprint')` from S10), on keyboard and controller alike. Deviation, to be decided by the lead: the setting is one per action, not one per movement preset as INP-002 words it; it can be keyed by preset once S10 exposes the movement preset.
- `always: true` rows (perfHud, botDebug) also work while a menu is open.
- Defaults are INP-003 (WASD, Space, C crouch, Shift sprint, LMB fire, RMB Alt, Alt walk, P prone, R reload, E use, Q ability 1, F ability 2, X ultimate, G grenade, N next grenade type, V melee, U gadget, H heal, Z ping, 1-9, wheel, Tab scoreboard, Esc pause, T comm, B buy menu, Y cards, F8 performance HUD, F9 bot debug view) plus pad defaults on the standard mapping (RT fire, LT Alt, A jump, B crouch, L3 sprint, X reload, Y next weapon, LB grenade, RB ability 1, d-pad left ability 2, d-pad up ultimate, d-pad right ping, d-pad down use, R3 melee, View scoreboard, Menu pause). Every one of the 16 standard buttons is taken, so a second layer uses chords: while View is held, a button with a `Pad:8+<button>` binding uses it instead (View + B walk, View + X gadget, View + Y comm, View + A heal, View + LB next grenade type, View + RB cards, View + R3 prone); View's own action (the scoreboard) waits, so a chord never fires it: held alone for `PAD_MODIFIER_HOLD` (0.25 s) it goes down (hold mode), a tap without a chord fires it on release (toggle mode flips it there), and a chord pressed after the hold lets go of it. `Input.bindingLabel('Pad:8+2')` = "View + X".
- M3 rows: `grenadeNext` (Next grenade type, N, pad View + LB `Pad:8+4`, touch: a swipe on `NADE`) writes `BTN.CYCLE_GRENADE` (`1 << 19`, S01); 12c `Gadgets.cycleGrenade(id)` makes the next carried grenade type the thrown one (bots do not press it). On touch a 24 px swipe on `NADE` (`swipeAction: 'grenadeNext'`, `TOUCH_SWIPE`) picks the next type and throws nothing; a still finger starts the cook after `TOUCH_COOK_MS` (150 ms) and a quick tap still throws. While two or more thrown types are carried, `Gadgets.syncCycleButton` (12c) writes the selected type's first word as the button's second line (`TouchInput.setNote('grenade', text)`, on a change only). `cards` (Use a card, Y, pad View + RB `Pad:8+5`, touch `CARD`) is an event row: 18j opens the `cardUse` screen while the match has active cards (`CardRun.slots`), else a toast.
- `Input.holdAction(index, down)` is a plain hold that ignores the Hold/Toggle setting; the touch stick's sprint uses it. Letting go of a plain hold also clears a toggle latched before it.
- Read state: `Input.effective[Input.actionIndex[id]]` (effective state after hold/toggle). `Input.isHeld(id)`, `Input.consumeBuffered(id)` and `Input.allConflicts()` are helpers of the test file `20b-test-input.js`, not game API.
- `Input.usePrompts` (list of `fn(id) -> text`): what holding Use does right now (`'HOLD TO PLANT'`, `''` = nothing); the HUD adds the bound key (17d). Producers push their own function.

### Bindings

Binding strings: `Key:KeyW` (KeyboardEvent.code), `Mouse:0`, `Wheel:up` / `Wheel:down`, `Pad:7` (standard mapping index). `''` = unbound. Each action has three slots: keyboard/mouse A, keyboard/mouse B, pad.

| Call | Effect |
|---|---|
| `Input.getBinding(id, slot)` | binding string |
| `Input.setBinding(id, slot, binding)` | returns the ids of other actions now sharing it (conflict flag), or `null` if the slot cannot take that binding (pad button on a keyboard slot) |
| `Input.resetBindings([id])` | defaults for one action or all |
| `Input.conflictsOf(id)` | ids of the other actions sharing a binding with `id` |
| `Input.bindingLabel(binding)` | display name; pad glyphs follow `Input.padStyle` (`letters`, `shapes`, `generic`) |
| `Input.captureNext(device, cb)` / `cancelCapture()` | rebinding: next press of `'kbm'` or `'pad'` goes to `cb(binding)`; Esc gives `cb(null)` (cancel), Backspace gives `cb('')` (clear) |

Saved in `Save.data.bindings[actionId] = [slot0, slot1, slot2]`, only for actions that differ from the default.

## Devices

- `Input.device`: `'kbm' | 'touch' | 'gamepad'`, last used. Emits `input.device` `{ device }` on change. Aim assist and assists in later sections key off it.
- Keyboard + mouse: pointer lock on a click while a match runs, `unadjustedMovement` when `controls.rawMouse` and supported (silent fallback to a normal lock), no OS acceleration applied by the game. Sensitivity `controls.mouseSensitivity` (0.05 deg per count at 1.0), `Input.cmPer360(sensitivity, dpi)` for the display, `controls.invertY`, `controls.adsMultiplier` while the aim action is held.
- Touch: see below. Gamepad: see below.
- Spectator hooks (UI-017, `17h-hud-spectate.js`): `Input.presses[actionIndex]` counts every physical press since boot (also taps shorter than a frame and presses of a Hold / Toggle row in toggle mode; wheel notches of button rows); `Input.moveAxes()` -> `Input.move { x, z }` (stick + keys, at most 1 long; `writeActor` uses it); `Input.spectate = fn(seconds)` is called once per input frame while a match runs when the local player is dead or absent (after `writeActor`; with no local player `applyLook(-1)` ran first and the frame's other input is dropped); `Input.spectating` (set by the spectator) keeps aim assist off the look.
- `Input.rumble(strength 0..1, milliseconds)`: strength is clamped to 0..1 and negative durations to 0 (a silent rumble does nothing); pad `vibrationActuator` (a rejected effect is swallowed) or `navigator.vibrate` with the duration scaled by strength; respects `controls.vibration`. Sources (INP-007): `damage` to the local player (strength = amount / 100, 160 ms), an `explosion` within 2x its radius of the player (fading with distance, 240 ms) and the player's own `weapon.fire` with a heavy, explosive, power, shotgun or sniper class (0.35, 70 ms); numbers in `RUMBLE` (05a).

### Pause rules (PLT-006)

`Game.pause(reason)` on: window blur (`'blur'`), tab hidden (`'hidden'`), pointer lock lost during play (`'pointerlock'`), pad unplugged while it was the active device (`'controller'`), the pause action and a back swipe or Back in a match (`'menu'`, 18p), a lost graphics context (`'graphics'`, S07), an upright phone (`'rotate'`, 18q). Every held, latched and queued input is dropped on pause. After Esc the browser refuses a re-lock for about 1 s: `Input.requestResume()` asks for the lock first and resumes when granted; if refused it emits `input.relock` (the UI closes its menus) and shows "Click to resume"; the next click locks and resumes. A running match without a lock shows "Click to play". `Input.resumeBlocked = fn() -> true` refuses Resume (S07 fills it with `Render.lost`: after a graphics context loss, `'graphics'` pause, the game resumes by itself on restore, PLT-005). The rotate guard (`RotateGuard`, 18q) pauses a running touch match on a portrait screen under 600 px wide (`ROTATE_PHONE_MAX_WIDTH`; an upright iPad plays on) behind the "Turn your phone sideways" overlay (`#rotate`), and asks `Input.requestResume()` once when the screen turns landscape; if the resume is held (a lost context, a pointer lock that needs a click) the pause menu's Resume does it. A pause the player chose stays.

### Aim assist (INP-008)

Only when `Input.device` is `touch` or `gamepad`, never for the mouse. A later section fills `Input.aimAssistTarget = fn(actorId, out) -> bool`: set `out.x/y/z` to the nearest valid hitbox point of a visible enemy, return false for none (cloaked). Sections that only need to refuse a found point push `fn(actorId, point) -> bool` to `Input.aimAssistFilters` instead of wrapping the hook (S12 refuses points behind smoke); `Input.findAssistTarget(actorId, out)` runs the hook and then every filter. Inside a 3 degree cone the look is slowed by 40% x strength; magnetism pulls toward the point at up to 1.5 deg/s x strength while the player looks, fires or aims, never overshooting (no snap). Strength settings `controls.pad.aimAssist` (default 60) and `controls.touch.aimAssist` (default 70); `Input.assistStrength()` raises it to the difficulty floor `Game.match.rules.botSkill.aimAssist` (0-100, -1 = none) and is 0 for the mouse. `Input.isToggleMode(actionId)` tells whether a hold action is set to toggle (ACC-004); `Input.resetToggle(actionId)` puts a toggled action back to off when its effect ended by other means (the scoreboard closed with its Close button). `Input.assist` `{ active, slowdown, error }` reports the last frame.

Touch auto-fire: `Input.autoFire` (setting `controls.touch.autoFire`, default on). Each frame the aim assist search (`Input.findAssistTarget`, the same single search aim assist uses, run for auto-fire even with the touch slider at 0) sets `Input.autoFireTarget` when the crosshair is within the target's torso width (`atan(TORSO_RADIUS / distance)`); the input layer then presses fire (touch device only). Per trigger (`Input.autoFireTrigger(id)`, filled by S11): an `auto` weapon holds fire; a `semi` or `burst` weapon presses on one sim tick and lets go on the next. Cloaked enemies and points behind smoke are never targets (the hook and its filters).
- Strength: touch `controls.touch.aimAssist`, gamepad `controls.pad.aimAssist` (never the mouse); `Input.aimAssistOverride = fn() -> 0..100 | -1` (S11 fills it from the match's difficulty, `rules.botSkill.aimAssist`) replaces the device setting, -1 keeps it. `Input.aimAssistFilters` (list of `fn(id, point) -> bool`) can refuse a found point (S12: smoke).

## Touch (05b)

`TouchInput` builds a DOM layer in `#overlay`: floating left stick (touch left of 42% of the width, or the dashed hint), look zone on the rest, one round button per row of `TOUCH_CONTROLS` (fire, Alt (button id `aim`, kept so saved layouts load; face `ALT`), jump, crouch `DUCK`, reload `LOAD`, swap, grenade `NADE`, heal, ability 1/2 `A1` `A2`, ultimate `ULT`, ping `PING`, pause, optional left fire, use, melee, gadget `TOOL`, card `CARD`, hold breath `HOLD`; the face text is 14 px and short). Rare actions are gestures, not buttons: a 24 px swipe on DUCK lies prone or gets up (`swipeAction: 'prone'`, `swipeNow`: crouch is pressed at once, so a held DUCK stays crouched; the swipe releases the crouch and any Toggle latch first, and does nothing in a movement preset without prone), a swipe on NADE picks the grenade type, a finger on the score panel holds the scoreboard (`TouchInput.panelAt`, 17c; Hold/Toggle setting), and PING held past 0.3 s opens the comm wheel (a tap pings). Old saved layouts that still name the removed LIE, TAB, CHAT and TYPE buttons load; those entries are ignored. Defaults (shares of the screen): top row y 0.20 (card, pause, ping), ability row y 0.32 (A1, A2, ULT, gadget), stick y 0.56, swap x 0.76, melee x 0.86. SWAP held 350 ms (`holdAction`) switches to the previous weapon. The stick's sprint (P2-05, setting `controls.touch.sprint`): `double` (default) = two pushes to the stick's edge (`TOUCH_SPRINT_ON` 90%) within `TOUCH_DOUBLE_PUSH_MS` 400 ms, in about the same direction (within `TOUCH_DOUBLE_PUSH_ANGLE` 45 degrees: a strafe jiggle through the centre is not a double push), with a dip under `TOUCH_SPRINT_REARM` 60% (or a lift) between them, so walking at full push never sprints; `instant` = one push past 90% (the old rule); `off` = the stick never sprints. A sprint ends under `TOUCH_SPRINT_OFF` 80% or when the finger lifts; `TouchInput.updateSprint(push, nowMs)` is the one rule, `stickSprints` still refuses it where sprint walks. A row with `need` shows only while `TouchInput.needs[need]()` is true (ability 1/2, ultimate, gadget, grenade and heal only while the player has what they use; the answers are re-read every frame by `TouchInput.syncNeeds`, which re-applies the layout when one changes, so a new match needs no re-apply): USE while the mode row has `useButton` (plant, defuse, arm, loot swap, chamber buttons: M08, M13, M20, M27, M31) or any fn in `TouchInput.useNeeds` is true (S11: revive in a team match with downed; S10: skimmer board on large maps); a need with no function reads the match flag `TouchInput.flags[need]`, set by `TouchInput.setFlag(name, on)` (the card button: 18j sets `cards` on `match.start` when the match has active cards, off on `match.stop`); the `BREATH` button (action `walk`: hold breath) reads the `breath` flag, which 11a sets while the player's scope sways (W24). Push past 90% sprints (released under 80%), unless `TouchInput.stickSprints()` is false (S10: the player's own movement preset, `Move.preset(Game.playerId)`, walks on sprint, e.g. Tactical or a hero row; the match preset when there is no player). Look: `controls.touch.sensitivity`, `controls.touch.acceleration`; tap-to-fire `controls.touch.tapToFire`; gyro `controls.touch.gyro` (`off|aiming|always`; asked only while the setting is not Off, iOS permission requested from the setting change or the next touch; when it cannot work (page not https, permission refused, no sensor data within 1 s) one toast says "Gyro needs HTTPS and motion permission" and the setting row's label is marked; only one 1 s sensor wait runs at a time). iPhone gyro needs the game served over HTTPS, not plain LAN http. Hooks: `TouchInput.weaponSlotAt(x, y)` (17a: the weapon slot under a point on the phone weapon bar, drawn above the ammo panel; a still tap on a box takes that slot, a drag there starts the stick) and `TouchInput.buttonLook(control)` (17g: the finger on PING also turns the look while the comm wheel is open). Fingers are tracked by pointer id in a pool of 10 slots. Four fingers down on the look area within 300 ms (none on the stick or a button, so a claw grip does not count) toggle the performance overlay and the bot debug view together (ARC-040); it works mid-match and in the touch layout editor. Gyro: a positive `rotationRate.beta` turns the view up, so pitch is the negated beta (yaw is the negated gamma). The layer is shown while a match runs on a touch device (`controls.touch.show`: `auto|on|off`).

Spectating (UI-017): while `TouchInput.flags.spectate` is true (set by 17h) `placeAll` shows only the `TOUCH_CONTROLS` rows marked `spectate` (`'always'`: stick, fire, Alt, reload, pause; `'free'`: jump and crouch, when `flags.spectateFree`) via `TouchInput.spectateShows(control)`, and `applyControl` writes their `spectateFace` (NEXT, PREV, VIEW, UP, DOWN) instead of `face`; the buttons keep their actions, so the spectator reads them as Fire, Alt, Reload, Jump, Crouch.

Layout (INP-005): presets `standard`, `compact`, `mirrored` ("Left-handed", setting `controls.touch.layout`). Left-handed is not a plain mirror: jump, heal, melee and swap have their own `mirrorAt` spots, the floating stick starts on the right (touch right of 58% of the width), and on phones the HUD's ammo, weapon bar, gadget and money cluster sits centre-right. `TouchInput.layoutOf/getProperty(id, key)`, `setProperty(id, 'scale' 0.5-2 | 'opacity' 0.2-1 | 'hidden' | 'position' {x,y})`, `resetLayout()`, `setEditing(bool)`, `select(id)`, `onSelect` callback. A control can never leave the screen. Placing (touch-01, `TouchInput.placeAll(width, height)`, on resize or rotation, settings changes and killcam start and end, never per frame): each shown button keeps its layout or editor place (`TouchInput.places[id]` = x, y, radius in pixels) when that spot is allowed and free, else takes the nearest free spot, moving at most `TOUCH_NEAR` (6) of its radii and staying on its own half of the screen (`keepsHalf`; only edge buttons and spots within `TOUCH_CENTRE_BAND` of the centre line may take either half), else shrinks (`TOUCH_SHRINK_STEP`) down to `TOUCH_SMALLEST` (45%) of its preset size but never below `TOUCH_MIN_DIAMETER` (30 px); when a half is too crowded every button on it is placed again a step smaller before one crosses over; last, the allowed spot that overlaps others least; a button that really meets another there (`place.overlaps`) makes both halves one step smaller and everything is placed again, so no button lands on another even with every button at editor scale 2 and HUD 150. Buttons keep a `TOUCH_GAP` (2 px). Placing also runs when the owned weapon count or a boss fight changes, and at most once a frame during an editor drag. Allowed = inside the safe-area layer (`TouchInput.insets` = `Hud.insets`), outside the aim zone (`TouchInput.aim`, `TOUCH_AIM_ZONE` 18% of the short side around the crosshair) and outside every HUD area the `TouchInput.keepClear` hooks register with `addClear` (17a vitals, ammo panel, the weapon bar for the owned weapons down to the ammo panel; 17f minimap; 17c score panel and its header rows; 17e killcam bars and their text; 17g Operations tickets, PvE rows and the boss bar during a boss fight). Bigger buttons are placed first; pause, ping and gadget (`edge`) stay in the top band or the top half of the side bands (`TOUCH_EDGE_BAND`). Buttons never overlap one another. Saved in `Save.data.touchLayouts[presetId][controlId] = { x, y, scale, opacity, hidden }`.

## Gamepad (05c)

`PadInput`: standard mapping, polled once per frame only while a pad is connected. Settings `controls.pad.innerDeadzone` (0.1), `outerDeadzone` (0.95), `curve` (`linear|classic|dynamic`), `sensX`, `sensY`, `invertY`, `aimAssist`. Look speed 200 deg/s at full deflection x sensitivity. Menu navigation (d-pad and left stick with key repeat, A accept, B/Menu back, bumpers prev/next) is emitted as `input.menu` `{ command }` while a screen is open. A pad with the standard layout is chosen over a non-standard one (a second odd device never silences the real pad; a pad with no standard layout alone is ignored with a toast). The pad takes the device from touch or the mouse only when a stick moves more than 0.3 from its rest position; a stick let go inside the deadzone sets a new rest position. Rebinding on a pad (INP-007): a button binds itself, View then a second button binds the chord `Pad:8+<button>`, View let go alone binds View, Start tapped binds Start, Start held 1 s cancels, View + Start clears. Hot-plug updates `Input.padStyle`; an unplug mid-match pauses.

## UI shell (18)

- `Ui.register(name, { build(root, params), onOpen, onClose, onBack, noBack, passthrough, overlay })`; `Ui.open(name, params)`, `Ui.back()`, `Ui.replace` (no production caller; only the self-test 20b-test-ui.js uses it), `Ui.closeAll()`, `Ui.current()`, `Ui.isOpen(name)`. Opening an unregistered name shows the toast "Coming soon". A screen whose `build` throws is logged and removed. `Input.uiOpen` is true while any screen is open (game actions are ignored).
- Navigation: keyboard arrows / Tab / Esc, gamepad via `input.menu`, touch taps. Inside a text field or textarea (`isTextField`, 05a) only Tab and Esc navigate; every other key belongs to the field (game bindings and the map editor keys ignore it too). Left/right adjust sliders and cycles. Focus is always drawn.
- `Ui.rebuild(container, build)` refills a container and keeps the focus on the control at the same position (screens that redraw themselves after a change). Settings screen hooks (`Ui.settingGroup`, `Ui.settingsFooter`, `Ui.settingsExtras[category + ':after']`), the Help screen (18n), crosshair editor, rules and economy panels: `docs/api/accessibility.md`.
- Builders: `Ui.button(text, onClick, className)`, `Ui.row(label, control)`, `Ui.cycle(options, labels, value, onChange)`, `Ui.toggle`, `Ui.slider({min,max,step,value,format}, onChange)`, `Ui.confirm({ title, text, yes, no, onYes })` (No, Esc and Back only close it), `Ui.toast(text)` (no placement argument: while a match is on (from `match.start`, before `Game.state` turns `playing`, until it ends) and not paused the toast goes to `Ui.playBox` (below the crosshair, clear of the header and the top touch buttons), else to `Ui.toastBox`). A screen registered with `inGame: true` (the scoreboard) is an overlay on a running match: game input keeps working and it takes no focus. `Ui.resetScroll()` scrolls the page back to the top when a text field loses focus (the iOS keyboard leaves the page shifted).
- Screens now: `main` (Quick Match, Play, Career, Custom, Range, Map editor, Settings, Help: Solo is a Career entry and the generated map a Custom > Map entry; entries whose screen is not registered are disabled "coming soon"; the list scrolls; on a short screen such as a landscape phone, under 520 px high, the buttons wrap into columns at least 180 px wide so every entry fits), `solo` (18o: Siege Waves, Endless Hold, Test Chambers with one difficulty choice), `guardian` (18o: the Guardian Plate choice), `pause`, `settings`, `bindings`, `touchLayout`, `help`, `confirm`, `saveTransfer` (opened by the "Back up or restore save" button, `Ui.settingsFooter`, under every Settings tab, 18l: Export fills a text box with `Save.exportText()`, Copy copies it, Download file saves it as a Blob link, Load file reads one into the box, Import confirms, runs `Save.importText` and restarts the page through `SaveTransfer.reload`; a bad paste or a failed write is refused with a toast and does not reload. When `Save.backupText()` finds a backup (the save an import replaced, or an unreadable one), a second row adds Export backup (shows it in the box) and Restore backup (confirm, then imports it)). Shared code box style: `textarea.ui-code` (18a).
- Save robustness (S04, PLT-003): `Save.migrate` replaces a top-level field whose kind differs from `Save.emptySave()` (`"settings": null`, a string for an object, an object for a list; a null default also takes an object). A failed write (storage blocked or full, or a save over 1 MB) sets `Save.notice` and emits one `toast` at once; a repeat of the same failure stays quiet until a write works again (`Save.lastFailure`). `Save.migrate` also repairs nested records and drops non-record entries from lists, and runs `Settings.sanitize` (a value its definition does not allow is dropped, numbers are clamped, a setting with an integer step is rounded). Every save carries a `revision` (the write count) and `Save.dirty` (an unwritten change: a flush writes only then); a save written by another tab with a higher revision is adopted, not overwritten, on the `storage` event, `pageshow` and when the tab becomes visible again, as long as this tab has no change of its own. `Save.importText` keeps the replaced save as the backup (`BACKUP_KEY`). A readable backup is never replaced by an unreadable save (A-05): `Save.backUpRecord(raw)` puts the unreadable record in `BACKUP_KEY` only when that slot is empty or unreadable, else in `SPARE_KEY` (`ctk.save.spare`, `Save.spareText()`). `backUpRecord` copies nothing when either slot already holds the same text (a kept newer save is met on every boot). A stored save with a `version` above `SAVE_VERSION` (written by a newer game, found at boot or adopted from another tab by `adoptNewer`) is played on from a migrated copy but never overwritten (A-04): `Save.keepNewerSave` backs the stored text up, sets `Save.notice` (shown once as a toast at the main menu) and `Save.keepStored`, which makes `saveNow` write nothing until an import replaces it (the newer text becomes the backup). The map editor refuses to save, rename or delete a map meanwhile, with the same notice text.
- Hooks for later sections: register `play`, `custom`, `range` (main menu entries; the Career screens open from Career) and `results` (opened on `match.end`); push `{ label, screen, when? }` to `Ui.pauseEntries` (pause menu rows, e.g. the rules panel; a section adds its rows on every `match.start` with `setPauseEntry(entry, true)` (18f) and a row that applies only to some matches has `when()`, read as the pause menu opens: false hides it, as the Buy menu and Loadout rows of 18f, Cards of 18j and Guardian Plate of 18o do); pause Restart starts `Progress.retrySetup(match.setup)` when the match belongs to a career run (ladder, challenge, operation, daily), else the same setup; push builder functions to `Ui.settingsExtras[category]`; `Ui.botDebug` (F9); `Ui.perfVisible` (F8); `Ui.selfTestRunner` (set by `20b-test-ui.js` to `Test.run`; Help > Run self-test calls it with `{ headless: true }`).
- A screen may define `onCommand(command)`: `Ui.onMenuCommand` asks it first and stops when it returns true (the map editor reads the pad itself, `docs/api/mapeditor.md`). A screen with tabs sets `element.tabStep(direction)` (`screenTabs`, 18b): `Ui.onMenuCommand` calls it for `prev` / `next` (pad LB / RB) and the focus follows to the new tab; Tab on the keyboard still moves the focus. Main menu entries: Range emits `ui.range`, Map editor opens `mapEditor`; the Custom Map tab opens `mapgen` (18h). Play, All modes and Match setup are described in docs/api/hud-play.md.
- Headless runs (`Game.headless`) open no menus on `ready`, `game.pause` or `match.stop`.
- `Ui.settingsExtras.controls` shows cm per 360, controller status and links to the bindings and layout editor.

### Performance overlay (18c)

`PerfOverlay`: DOM text refreshed 4 times a second while visible (`developer.perfHud`, F8; a four-finger tap toggles it and the F9 bot debug view): fps, frame p50/p95/p99, sim p95, render/hud/audio/gpu ms, draw calls, triangles, render scale, actors, bots (alive hostile or friendly bot actors), the AI system cost (all sim systems named `ai*`, `bot*` or `pveBrains`), projectiles (`Projectiles.active`, copied by `Perf.publishCounters()` each frame), particles, dropped steps, JS heap (Chrome), device, bot debug, the five slowest sim systems and the last three `ErrorLog` entries (repeats are folded into one line, `(xN)`; when the session's first error has rolled out of that tail it is shown as a `first:` line). Turns red under 60 fps. Reads `Perf.stats()` and `Sim.timing` at runtime (S19 loads after S18 but the loop starts after boot).

### Device helpers (18p) and the rotate guard (18q)

`Device` (18p, iPhone and iPad, Home Screen web app): asks `navigator.storage.persist()` on the first tap or key (`Device.persistResult`); after the first finished match, in an iOS Safari tab whose save was not made persistent, one dialog on the bare main menu says to back up and add the game to the Home Screen (it opens `saveTransfer`; `Save.data.tips.homeScreen` marks it, once ever), and the Home Screen app's first start (an empty save) offers the import. A running, visible match holds the Screen Wake Lock (`navigator.wakeLock`), released on pause, in menus and when the page hides; a refused request or a lock the system lets go (iOS Low Power Mode) is asked for again after `WAKE_RETRY_MS` (5 s). Settings > Video shows "Full screen on or off" where the Fullscreen API exists (Android, iPad). One history entry per match, so a back swipe pauses (`'menu'`) instead of leaving the page. The version label shows in menus only. `RotateGuard` (18q) is described under the pause rules.
