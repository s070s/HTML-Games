# HUD (S17) and match flow screens (S18 add-ons) - public API

Files: `src/17a-hud.js` (core, settings, layout, pen, projection, status panels), `17b-hud-combat.js` (crosshair, scope, hit / kill markers, damage numbers, damage arcs, vignette), `17c-hud-match.js` (header, kill feed, banners, respawn text), `17d-hud-markers.js` (world markers, name tags, item timers, captions, sound ring), `17e-hud-killcam.js` (killcam-lite), `18d-ui-play.js` (Quick Match, Play and results screens, `PlayFlow`), `18e-ui-scoreboard.js` (scoreboard screen, `LocalPlayerStats`). Tests: groups `hud` (`20b-test-hud.js`) and `play` (`20b-test-play.js`).

More elements (minimap, compass, awareness, barks), the Hardcore HUD rule, `hudAddElement` and the `keepInHardcore` argument of `Hud.register`: `docs/api/accessibility.md`.

## How the HUD is drawn (REN-005, PERF-002)

- WebGL quads only, no DOM. Four `HudBatch` layers, one draw call each: `hud.back` (10: scope, vignette, damage arcs), `hud.world` (20: markers, name tags, item timers, damage numbers), `hud.main` (30: crosshair, status panels, header, kill feed, captions, sound ring), `hud.front` (40: banners, respawn text, killcam panel).
- Drawn only while `Game.state === 'playing'` and `hud.show` is on (also while paused: the pause menu is DOM on top). The first layer calls `Hud.beginFrame(seconds, width, height)`: it advances `Hud.time` (the UI clock, frozen while paused) and recomputes the layout.
- A drawer is `Hud.register(layer, id, element, draw(pen, layout, seconds))`. `layer` is `'back' | 'world' | 'main' | 'front'`; `element` is a `HUD_ELEMENTS` id (its toggle `hud.element.<id>` hides the drawer) or `''` for always on. A drawer that throws is logged once and switched off, the others keep drawing. `Hud.quadsOf(element)` (quads an element drew in the last frame) exists only in the test file `20b-test-hud.js`.
- Cost: a busy scene (about 420 quads: all panels, feed, markers, captions) measures 0.11 - 0.17 ms per frame in the headless self-test on the dev PC (budget 0.4 ms); the `hud` test group asserts it.
- No allocation per frame: numbers and times come from cached strings (`hudNumber`, `hudCount`, `hudTime`), events write into fixed rings of typed arrays, scratch objects are reused. Only `Items.activePowerups`, `Items.timers` and `Abilities.hudState` allocate what their owners put into the arrays they fill.

## Layout

`Hud.layout`: `width height unit margin left right top bottom centerX centerY compact touch` plus anchors for the stacks around the screen (`ammoRight ammoWidth ammoHeight abilityY powerupY gadgetY moneyY weaponBarY`). `unit` = `clamp(min(width / 1100, height / 620), 0.9, 1.5)` x the player's HUD scale: 1 at the design size, so the smallest text (14 units) is never below 14 px at 100% scale (ACC-008). Safe-area insets come from the CSS `--safe-*` variables (`Hud.insets`, measured at boot and on resize) and move `left right top bottom` inwards. Compact layout (`hud.compact` `auto` = touch or a screen under 520 px high): smaller bars and ammo panel, three kill feed rows, no weapon bar except on touch, and on touch the ammo panel sits bottom centre-left (centre-right in the left-handed touch preset) so the touch buttons stay free. On phones the weapon bar is drawn above the ammo panel (`layout.weaponBarY`, `layout.ammoHeight`; the money and gadget stacks move up with it): a still tap on a box takes that slot, a drag there starts the stick (`TouchInput.weaponSlotAt`, 05b).

## The pen (`Hud.pen`)

`rect line ring text label(text with a shadow) panel(dark backing) bar(track + fill) triangle quad shape(kind 'circle' | 'square' | 'triangle' | 'diamond') octagon weaponIcon(class) measure(text, size) measureAt(text)` - HudBatch calls. `HudPen.measure` / `measureAt` give the width at the size the text is drawn: a size under the floor (`Hud.textFloor`, 14 px at 100% scale, the one rule `hudFloorTextSize`) is floored for measuring too, so layouts built from widths match the drawn text. HUD drawers measure through the pen, never with `HudBatch.measure`; `hud.opacity` scales every alpha through `HudBatch.alphaScale` (applied once per call in `setHudPaint`, 07f).

Scratch forms for the every-frame drawers (PERF-006): fill the scratch array, then call the `*At` form with only the colour, align and alpha. `hudBoxAt` (x, y, width, height, bar share) -> `rectAt panelAt barAt`; `hudShapeAt` (x, y, half size) -> `shapeAt(kind) weaponIconAt(class)`; `hudTextAt` (07f: x, y, size; the width lands in `[3]`) -> `textAt labelAt` (and `HudBatch.measureAt(text)`); `hudRingAt` (07f: x, y, radius, thickness, start, end) -> `ringAt`, `hudDrawCooldownRingAt(pen, remaining, color)`. The argument forms set the same scratch and call these. Why: the once-per-frame drawers run in the middle compiler tier for most of a match, which boxes every float argument of a call it does not inline (3-4 per pen call); the drawers of the main layer use the scratch forms only (a `perf` test checks their source). Colours are numbers (0xRRGGBB). `HUD_WEAPON_ICONS` draws a silhouette per weapon class from rectangles.

## Settings (all in the generated Settings screen)

| Key | Default | Notes |
|---|---|---|
| `hud.show` | true | the HUD toggle |
| `hud.scale` | 100 | percent, 50-150 |
| `hud.opacity` | 100 | percent, 30-100 |
| `hud.compact` | auto | auto / on / off |
| `hud.element.<id>` | true | one per `HUD_ELEMENTS` row: `crosshair hitMarkers damageNumbers(off) vitals ammo weapons gadgets abilities money powerups itemTimers(off) damageArcs vignette header killFeed markers nameTags banners respawnText captions(off, accessibility) soundRing(off, accessibility)` |
| `hud.crosshair.style` `size` `gap` `thickness` `outline` `color` `dot` `dynamic` | cross 9 4 2 on white off on | UI-004; `style` cross / dot / circle / T / chevron |
| `hud.scopeOverlay` | true | dark scope ring for weapons with `alt.zoom` >= 2.5 |
| `hud.killcam` | true | killcam replay after your death |
| `hud.teamShapes` | true | team shape next to team colour (ACC-001) |

## Elements and what they read

- Vitals: `Actors.health/armor/shield` + `max*`; overheal draws a gold line; low health pulses (reduce-motion aware).
- Ammo: `Weapons.currentWeapon/ammo/magSize/state`; LOW AMMO at <= 25% of the magazine, RELOAD / NO AMMO, a reload progress bar. Weapon bar: owned weapons by slot. Key hints in prompts come from `hudBoundLabel(actionId, device)` (the first binding of that device, `''` when unbound, so callers show their own fallback).
- Gadgets `Gadgets.hudState(id, out)` (then the carried loot consumables, `Items.consumableCount`, with the heal key and a ring from `Items.useProgress` while one is in use), abilities and meter `Abilities.hudState(id, out)` (`cooldown` is the fraction **remaining**, 0 = ready), money `Economy.hudState(id, out)` (shown for `roundBuy` / `waveShop` economies, or whenever money, income or a buy phase is non-zero), powerups `Items.activePowerups(id, out)`, item timers `Items.timers(out)` (within 40 m, on screen).
- Crosshair: `Hud.crosshairFor(weapon)` = settings, then `Hud.crosshairOverride(weapon, out)` (default hook: class table `HUD_CLASS_CROSSHAIRS`, then the player's `Save.data.crosshairs[weaponId]`; set with `Hud.setCrosshairOverride(weaponId, fields | null)`; fields `style size gap thickness outline color dot dynamic hidden`). The gap grows with `Weapons.spreadDegrees` converted to pixels with the camera FOV (smoothed, capped).
- Hit marker (white, gold for a head hit), kill marker (red cross): from `damage` events with `source` = you (kinds hit, melee, beam, splash) and `kill` events with `killer` = you. Damage numbers stack per target for 0.7 s.
- Damage arcs: `damage` events with `target` = you; the bearing follows the attacker's live position (clockwise from straight ahead). Vignette below 40% health, red only; the short red hit tint is limited to 3 per second (`Hud.flashAllowed()`, ACC-005).
- Header from `Modes.hudState()`: team scores with team shapes, FFA rank / score / leader, the clock (red under 30 s), OVERTIME, GET READY / ROUND OVER, FIRST TO n, round pips, control meters, objective chips (letter, owner colour, capture arc, contested ring, bomb countdown, flag state). Kill feed: `kill` events, oldest first, 6 s, newest 5 rows (3 compact), weapon icon + head icon. Banners: `announce` events and your own `medal` events (`CAT.medals` row name when it exists, else the id in words). Respawn text: `Modes.hudState().respawnIn` (countdown, "press fire", ELIMINATED).
- Markers (`Hud.project`): objectives from `Modes.objectives` (letter / shape, distance), pings from `ping` events of your side (`HudPings`, 12 slots, the other side's pings are not stored: each kind lives its `COMM_CALLOUTS` row's `seconds`, 6 s without a row; at most `HUD_PING_PER_ACTOR` 3 live per sender, the fourth replaces its oldest; an enemy ping with a `target` follows that actor while the pinger sees it, a line-of-sight check every 0.2 s, and stays at the last seen spot otherwise (both the world markers and the minimap call `HudPings.follow`, so either view keeps it moving alone); a reply shows its label, e.g. Dibs, over the sender's name; the minimap reads the same `HudPings.live`), off-screen arrows on the edge, teammate name tags (<= 60 m, never enemies), captions and the visual sound ring from `caption` events (shape per kind: footstep circle, gunfire triangle, explosion diamond, item square, voice disc, alert triangle). HP-007 downed cues (17d, only while `Damage.downedCount` > 0): drawer `downedAllies` (world, element `markers`) puts a warn diamond with distance over each downed teammate; drawer `downed` (front, element `respawnText`) shows DOWNED with the bleed-out time (`Damage.downedTime`) and a revive ring while a teammate revives you, the revive ring (`Damage.reviveProgress / REVIVE_SECONDS`) while you revive, and the Use key with HOLD TO REVIVE within 4 m of a downed teammate.
- Comm wheel (17g `CommWheel`, an `Input` source, front layer): hold Comm (T) or hold Ping 0.3 s (keyboard Z, pad d-pad right, touch PING); look input picks one of the `COMM_CALLOUTS` (14f) on a ring around the crosshair (on phones `commWheelPlaceRing` fits the ring below the ability row and beside the grenade button, mirrored for the left-handed preset, so no label sits under a default touch button) instead of turning the view; letting go sends `BotTeam.callout` (to the team bot aimed at when it opened, named under the crosshair as ORDERS TO, else SQUAD) or, for a reply, `BotTeam.reply` to the newest teammate ping; a short Ping tap sends `BotTeam.playerPing` (docs/api/bots.md). `CommWheel.stepPing` (sim step) catches a tap shorter than a frame: it sets `pingEdge` when a step sees a Ping press that no frame saw held (`pingSeen`). The look it takes already carries the invert-Y settings.
- PvE status (17g, element `pve`, UI-003, NPC-008, DIF-004) from `Modes.hud.pve` (`PVE_HUD`, `docs/api/pve.md`) while `active`: under the header one panel per mode (`HUD_PVE_PANELS`): Siege Waves / Endless Hold show wave of the total, the phase (NEXT WAVE countdown, ENEMIES left, EXTRACT), the core bar with its shield bar, retries and GUARDIAN PLATE when worn; Mote Bank carried motes of `PVE_BANK.carryMax`; Fiends and Attrition enemies left; the stealth contract the awareness meter of `awareness` (`hudAwarenessColor`) with UNSEEN / SUSPICIOUS / SEARCHING / ALERT from `Pve.awarenessState` of the most aware living guard (the thresholds stay in 14h), alarms, score and the relic; Test Chambers chamber of the total, the timer in the colour of the medal it still earns (`chamberMedal`), EXIT OPEN / LOCKED, steps and gates. The boss bar (`PVE_HUD.boss` = `PveBoss.hud`: name, health, phase of phases with pips, WEAK POINT BROKEN) sits under it. Right side: the chamber medal table (par time from `parTime`, steps and gates from the `PVE_CHAMBERS` row, per medal; stars, last medal) and the Firing Range drill table (shots, hits, accuracy, headshots, damage, kills, drill kills of targets, drill time, best drill, drills done); on a touch device (`layout.touch`) the right side holds the buttons, so both tables sit under the status rows and end 40 units left of the crosshair, with 17-unit rows on a compact HUD (19 otherwise). Numbers of 1000 or more (the core, a contract score, range damage) come from the `hudNumber` cache of 17a too: one string per new value, none per frame. Bottom centre (on touch: 20 units higher, centred on the ammo panel, which sits bottom centre-left: 17a `layout.ammoRight`, `layout.ammoWidth`, and ending left of `HUD_PVE_TOUCH_NOTE_RIGHT` (55% of the width) so no default touch button is covered; `hudPveNoteRect` is the one note box for the drawing and the layout test): the chamber `hint` and, while `guardianOffer`, the Guardian Plate prompt (CHOICE text until `PVE_HUD.guardianAccepted` is set, then READY; phones get the short `_TOUCH` texts).
- Operations tickets (17g, drawer `tickets`, element `header`): while `OperationRun.active`, both teams' `OperationRun.tickets` under the scores; at or under `OPERATION_WARN_TICKETS` in the bad colour.
- X35 / X36: `HudExtra.readRules` reads `rules.fx.radar` (mode, range) on `match.start`; `Hud.applySettings` reads `rules.fx.noHud`. The `hudui` self-test starts matches with the `radar` and `hardcore` mutators and checks both.

`Hud.project(x, y, z, out)` -> true when the point is in front of the camera and on screen; `out` (default `hudProjection`) gets `x y depth distance dirX dirY` in CSS pixels; it matches the renderer's matrices (tested against `Mat4`).

## Killcam-lite (UI-011)

`Killcam` records every actor's `x y z yaw pitch eye` plus a living flag at 20 Hz in a fixed ring (44 frames, typed arrays, sim system `killcamRecord` at order 95). When the local player is killed by another actor (and `hud.killcam` is on and at least 0.3 s of history exists) the last 2 s replay from the killer's eyes: `Render.cameraOverride` places the camera, `Render.replayPose` is set to `killcamPose`, so every body (07c `fillActors` and the PvE source) is drawn where the recording has it, with its own model; the killer's body is not drawn, nor bodies that were not alive then. It also records the held weapon index per actor and frame (`Killcam.weapons`, from `Render.heldWeapon`); while it plays, `Render.heldWeapon` answers with the recorded weapon. `Killcam.looks` keeps 7 values per actor and frame (speed, height, grounded, cloak, health share, shield share, champion; read from the frame last sampled, not blended), so a replayed body walks, crouches and shows its health shade, shield and champion ring as it did; cloak 1 (cloaked) hides it, cloak 2 (Ghostveil) shimmers by the replay clock (`ghostShimmerVisible`, 12b). The panel shows killer name, weapon, headshot and the killer's health / armor / shield at the moment of the kill, a progress line and a skip hint. It ends after the replay plus 0.25 s, on respawn, on `match.end` / `stop`, or when the player releases and presses fire / jump / use after 0.35 s. `Killcam.sample(id, simTime)` returns the interpolated transform (reused object).

**Hook chaining:** 17e wraps whatever `Render.cameraOverride` and `Render.actorStyle` held when it loaded (items, abilities and the renderer fill theirs earlier). A section that assigns either hook later must chain the previous value the same way.

## Scoreboard (UI-010, MODE-003)

Screen `scoreboard` (overlay, passthrough). Tab / the pad's View button: hold to look; touch: tap to open, tap again or Close to hide (with `controls.toggle.scoreboard` on, Input keeps the toggle on every device and the board closes on the reported release; closing it any way resets that toggle). It opens by itself at the end of a round and closes when the next round starts (`round` events). Rows are live from `Modes` during the match and from `Game.match.results` afterwards: player (team symbol + colour, dead greyed, local row highlighted), score, kills, deaths, assists and an objective column (`Captures`, `Plants`, `Hold time`, ... by `rules.objective`, or `Objective` when anyone has objective points); team modes add a block per team with its score and rounds. Below: `LocalPlayerStats` for the local player - per weapon shots, hits (one per shot even for pellets), accuracy, kills, headshots (from `weapon.fire`, `damage`, `kill` events) - and the medals earned (`medal` events). `Scoreboard.renderInto(container)` is shared with the results screen. `LocalPlayerStats` resets on `match.start`.

## Match flow (PRG-001, UI-001)

`PlayFlow` (no DOM):

- `Bus 'ui.quickMatch'` -> `PlayFlow.quickMatch()`: starts the remembered setup in the same call (so the click can lock the pointer). Remembered in `Save.data.play = { mode, map, ruleset, bots, difficulty, team, length }` on every start; an invalid or outdated record is repaired by `PlayFlow.normalize` (unknown mode -> ffa, a map that does not list the mode -> the smallest one that does, bots capped by `Quality.current().bots`, a missing mode default bot count). Defaults: `ffa`, the smallest ffa map by floor area (`spire`), 7 bots, the mode's own ruleset (RS01 `classic`), difficulty `regular`.
- `PlayFlow.buildSetup(choice, random)` -> `{ mode, map, mutators: [], bots, seed, difficulty, player: { team, name: 'You' }, ruleset?, modeOptions? }` (`ruleset` only when chosen; `modeOptions` = the mode's score, time and ticket limits scaled by the match length, Short 0.5x, Standard 1x, Long 1.5x, starting from the score limit the ruleset builds (`Rules.build`; the Play screen shows it too: hero Team Clash plays to 15, Short 10, Long 25, because of the hero kill limit), rounded up to 5 points or tickets and 30 s, absent for Standard, for round modes and for modes without limits: `choice.length`, `PlayFlow.hasLength(mode)`; `PlayFlow.hasTeamChoice(mode)` says whether the Play screen shows the team row). Bots come from `PlayFlow.rosterBots(count, difficulty, seed)`: named roster bots `{ profile }` picked by the seed, first those whose tier the difficulty allows, then the others held inside its range (the bot gets an explicit `tier` including the adaptive shift); a field larger than the roster is filled with empty objects, which the bots section tiers from `setup.difficulty`. A Generated map Play (18h) and a Custom match with the mixed personality (18g) use the same roster. Team modes let the player pick a side (`hasTeamChoice`) unless the mode has `params.fixedSides`.
- `PlayFlow.start(choice, random)`, `shuffle(random)` (random playable mode, a map listing it, bots 3..default, random difficulty; ruleset stays the mode's), `playAgain()` (same setup, new seed; with a winner-stays `results.queue` (M03 duel) the bots are reseated in queue order by `queuedBots(bots, results)`: the winner stays, the next queued bot comes in, the loser waits last; each reseated bot keeps its name and tier, plus any adaptive tier change since `Bots.setupShift`), `nextMap()` (same mode and rules on the next map that lists it; not for career matches), `outcome(results)` (`win | loss | draw | over`), `winnerName(results)`, `playableModes()` (modes with a registered behaviour that a map lists), `mapsFor(mode)`, `difficulties()` (`CAT.difficulty` rows when that catalogue exists at runtime, else one `Regular`), `maxBots()`.
- Screens: `play` (mode, map, rules, bots slider, difficulty, match length for modes with limits, team for team modes, Start, Shuffle, Loadout; the main menu's Play entry turns on) and `results` (opened by the `match.end` listener of 18b: Victory / Defeat / Draw, winner, reason, your stats, the scoreboard tables, then the buttons: for a career match the next step (`Progress.nextStep`, e.g. Next match, Next map) as the primary button and `Progress.replayLabel(setup, outcome)` (Retry after a loss, Play again, none after an operation map) for the replay; for a plain match Play again and Next map; Main menu = `Game.stop()`). The results screen releases the pointer lock. Pause > Restart starts `Progress.retrySetup(match.setup)` for a career run (ladder, challenge, operation, daily: a new seed and the run's own next setup), else the same setup.

## Events

Consumes `damage kill weapon.fire medal announce ping caption actor.spawn round input.action match.start match.stop match.end setting boot`. Emits nothing new.

## Known limits

No touch gesture for hiding the HUD (the Hardcore HUD mutator and `hud.show` hide it; minimap, compass, awareness meters, bark lines, scope info, flash and suppression effects are in `accessibility.md`). The minimap is a radar without walls. The killcam replays positions and view direction, not animations, projectiles or effects. The vignette is red edge bands (no blur).
