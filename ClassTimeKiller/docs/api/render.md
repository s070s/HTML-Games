# Renderer API (S07)

Files: `src/07a-render.js` (core, post, context loss, settings), `07b-render-world.js` (static world, sky), `07c-render-actors.js` (instanced shapes, actors), `07c-render-models.js` (`Models`: the one builder of gear, weapon and projectile models), `07d-render-fx.js` (`Fx`), `07e-render-view.js` (camera, view model, quality control), `07f-render-hud.js` (`HudBatch`), `07g-render-weapon-anim.js` (the P6 weapon animation layers: `ViewAction`, `ViewLayers`, `ActorAction`). Data: `src/03b-data-render.js`, `src/03b-data-animations.js` (`reloadAnims`, `meleeAnims`), body models `src/03s-data-models-actors.js`, `src/03q-data-models-weapons.js`, gear models `src/03r-data-models-gear.js`. Tests: `src/20b-test-render.js`, `src/20b-test-models-actors.js` (group `render`), `src/20b-test-anims.js` (group `anims`).

When `Game.headless` is true at boot, or WebGL2 is missing, nothing is created: every hook below stays a cheap no-op (`Fx.*` return at once when `Game.headless`). Missing WebGL2, a shader that fails to build, or a rebuild that fails after a context restore shows the PLT-002 fatal screen ("WebGL2 is required").

S07 never calls `World` (S08 is a later section): the static world arrives through the `Render.worldQuery` hook, and every ray the renderer needs (baked sun shadows, map lights, the blob-shadow ground probe) runs against a brush grid built at bake time (the shared `BrushGrid` of S01, 8 m cells over the brushes' xz bounds).

## Hooks for later sections

| Hook | Contract |
|---|---|
| `Render.worldQuery` | **S08 sets it to `World`** (one line in `08a-world.js`). The renderer reads only `Render.worldQuery.brushes` (convex brushes `{ material, minX..maxZ, planes, planeCount }`) on `world.load`. While it is `null` the world mesh is empty. |
| `boxVisible(minX, minY, minZ, maxX, maxY, maxZ)` / `boundsVisible(box)` | frustum test of an axis-aligned box; `boundsVisible` reads `minX..maxZ` from an object (world chunks: no float arguments, PERF-006) |
| `Render.addSource(name, fn(batch))` | Called once per rendered frame. Push shapes with `batch.mesh(shape, x, y, z, yaw, pitch, sx, sy, sz, r, g, b, emissive)`. `shape`: `box sphere cylinder capsule cone wedge ring disc` (unknown names are ignored; `disc` is the flat disc of the blob shadow). `(x, y, z)` is the centre, `sx sy sz` the full size in metres along the shape's local axes, angles in radians (yaw 0 looks +Z; positive pitch tips the local +Z axis up; local +Y tips forward with pitch -PI/2), `r g b` 0..1, `emissive` 0..1 (self-lit). Cylinder, cone, capsule, ring and disc are built around their local Y axis. A wedge rises toward local +Z. A source that throws is logged once and switched off. Capacity: 1024 instances per shape per frame (extra ones are dropped and counted in `Render.stats.droppedInstances`). `mesh` returns the instance's float offset in `batch.data`, or -1 when the shape is unknown or the region is full. Zero-allocation form for hot callers (PERF-006: float arguments to a call that is not inlined are boxed on the heap): `o = batch.reserve(shape)` (offset or -1), write `batch.data[o..o+11]` = `x y z yaw sx sy sz pitch r g b emissive`, then `batch.light(o)`. Or keep one `instance = makeShapeInstance()` record (`x y z yaw pitch sx sy sz r g b emissive`), fill its fields and call `batch.meshFrom(shape, instance)` (same result and return value as `mesh`). The record comes from a constructor (`ShapeInstance`), not an object literal: V8 shares field types between literals with the same property count and first keys, and a field that ever held an array or object boxes every float stored into it, so never build these records as literals. Each instance's sun term comes from `sunVisibilityAt(batch.data, offset)` (07b: the grid byte, 0..`SUN_LIT`; the 0..1 float form `sampleSunVisibility(x, y, z)` exists only in the tests, `20b-test-render.js`). Test doubles of `batch` that a source may receive should offer `meshFrom` too. |
| `Render.addActorStyle(fn(id, out))`, `Render.actorStyle` | Called per drawn actor: every `addActorStyle` function in load order, then the single `actorStyle` override (tests, debug). `out = { r, g, b, emissive, scale, visible }` arrives filled with the default look (team colour, else the profile `color`, else a palette colour by id; `visible` is false while `ACTOR_FLAG.INVISIBLE` is set). Change fields in place (powerup glow, cloak, giant mode). |
| `Render.camera` | `{ x, y, z, yaw, pitch, roll, fov }`. Each frame it follows `Game.playerId`: interpolated feet + smoothed `Actors.eye` (+ optional head bob), angles = `Actors.aimYaw / aimPitch` (the freshest input). `fov` = setting `video.fov` divided by the aim zoom. |
| `Render.cameraOverride = fn(camera)` | Return `true` after placing the camera (spectate, killcam, menu fly-by). `Render.view.alpha` holds this frame's sim interpolation alpha for an override that follows a moving actor. While it returns true the local player's body is drawn and the view model is hidden. `roll` is applied. Owners, in chain order: S12 (puppet eyes), the map editor, the killcam (17e), the spectator (17h: after the killcam, `Spectate.place`). |
| `Render.viewModel = fn(out)` | Filled by S11. `out = { visible, shape, model, kick, reload, swap, ads, color, zoom, recoilPitch, recoilYaw, dual, charge, chargeFraction, ...animation fields }` is reset every frame to `{ false, 'rifle', '', 0, 0, 0, 0, '#4a5058', 1.15, 0, 0, false }`. `model` = the weapon id: its own model (03q `weaponModels`) is drawn, else the class row of `shape`. `recoilPitch` / `recoilYaw` = recoil punch plus scope sway (W24) in degrees (positive pitch = up), added to the camera's aim angles (view kick); `dual` draws a mirrored second gun in the left hand. `shape` = weapon class (`sidearm shotgun rifle smg lmg dmr sniper rail launcher energy heavy melee tool exotic power`, unknown = rifle). `kick`, `reload`, `swap`, `ads` are 0..1 animation amounts (kick 1 = full recoil this frame; reload 0 -> 1 over the reload; swap 1 = fully lowered: it runs 0 -> 1 over the first 35 % of the swap time with `model` the weapon in hand, then 1 -> 0 over the rest with `model` the pending weapon; a swap changed mid-way carries on from the weapon and level drawn). `color` = weapon body colour. `zoom` = FOV divisor at full `ads` (sniper scopes: e.g. 4). `charge` is in seconds (it was documented as 0..1); `chargeFraction` = `charge` over the charging mode's `charge.time`, 0..1. The animation fields are listed under "Weapon animation (P6)" below. |
| `Render.replayPose = fn(id, pose)` | Filled by S17 while the killcam plays: returns `true` when the body is drawn, at the recorded pose it wrote into `pose` (also `recorded`, `speed`, `height`, `grounded`, `health`, `shield`, `champion`, which 07c and 14h read instead of the live state); `null` = live bodies. |
| `Render.teamSlot = fn(team)` | Filled by S17 (`Hud.colorSlot`): the team colour slot bodies wear; `null` = the team itself. |
| `Render.heldWeapon = fn(id)` | Filled by S11: the `CAT.weapons` index an actor holds (the one being raised during a swap), -1 none. In third person the weapon's model replaces the actor's `gun` part (none, or no hook: the plain part). |
| `Render.actorAction = fn(id, out)` | Filled by S11 (P6): what the body of actor `id` does with its weapon: `out = { kind: 0 none | 1 reload | 2 melee | 3 swap, swap (the lowered level 0..1), reloadSet, reload (0..1), reloadEmpty, reloadFirst, reloadLast, meleeAnim, meleeAge, meleeCycle, meleeCount, fireHeld, meleeStriker, weaponIndex, blocking }` (the field names of the view model record). Read by 07g `computeActorAction` from 07c `animateActor` for near and far bodies. |
| `Fx.burst(kind, x, y, z, nx, ny, nz, count, colorHex)` | Particles from a point along the normal. `kind`: a `CAT.fxKinds` id (`spark smoke dust blood muzzle explosion energy water fire frost shock heal`, unknown = spark). `count <= 0` uses the kind's default. `colorHex` (`'#rrggbb'` or `0xrrggbb`) overrides the kind colour; omit or pass `null` to keep it. Pool size = quality `particles` (oldest reused). |
| `Fx.tracer(ax, ay, az, bx, by, bz, colorHex)` | A glowing streak from A to B for 0.09 s. |
| `Fx.decal(x, y, z, nx, ny, nz, kind)` | A mark on a surface. `kind`: a `CAT.decalKinds` id (`bullet scorch blood energy frost paint`). Ring buffer of quality `decals` (Potato 0 = none). |
| `Fx.light(x, y, z, colorHex, radius, seconds)` | A fading point light. 8 slots; the quality row's `lights` (8/4/2/0/0) are applied per frame. |
| `Fx.clear()` | Empties every pool (also on `match.stop`). |
| `HudBatch.addLayer(name, order, fn(hud, seconds))` | S17 registers HUD layers; lower `order` draws first. Each layer is one draw call. A throwing layer is logged once and switched off. There is no `removeLayer` (tests splice `HudBatch.layers`). |
| `HudBatch.rect(x, y, w, h, colorHex, alpha)` | Filled rectangle. Coordinates are CSS pixels from the top-left; `hud.width` / `hud.height` give the screen size. |
| `HudBatch.text(string, x, y, sizePx, colorHex, align, alpha)` | `y` is the middle of the line; `align` `'left' | 'center' | 'right'`. Returns the width. `HudBatch.measure(string, sizePx)` returns the width without drawing. System font, ASCII plus `° × • – — … ← ↑ → ↓ ★ ♥ ▲ ▼ ●`. |
| `HudBatch.ring(x, y, radius, thickness, colorHex, alpha, start, end)` | Ring or arc; angles in radians, 0 = 12 o'clock, clockwise; omit start/end for a full ring. |
| `HudBatch.line(x1, y1, x2, y2, thickness, colorHex, alpha)` | A straight line. |

Budget: 8192 HUD quads per frame (extra quads are dropped and counted in `HudBatch.dropped`). Zero-allocation quad (07f, PERF-006): fill `hudCorners[0..7]`, set the paint once per drawing call with `setHudPaint(colorHex, alpha)` (it multiplies the alpha by `HudBatch.alphaScale`, the HUD opacity setting that S17 keeps there), then call `pushHudSolid()` per quad (or fill `hudCorners[8..11]` with a texture rectangle and call `pushHudCorners()`). There is no argument form: a float passed to a call that is not inlined is boxed. `HudBatch.line`, `HudPen.quad` and `triangle` fill the scratch directly; the pen passes its alpha through unchanged. `pushHudBox()` takes left, top, right, bottom in `hudCorners[0..3]` and spreads them to the four corners. Text and rings also have scratch forms: `HudBatch.textAt(string, colorHex, align, alpha)` and `measureAt(text)` read x, y and size from `hudTextAt` and leave the width in `hudTextAt[3]`; `HudBatch.ringAt(colorHex, alpha)` reads `hudRingAt`; `text`, `measure` and `ring` fill the scratch and call them. Text quads are one per visible glyph; a full ring is 48 quads.
- Actor style fields (`Render.addActorStyle(fn(id, out))`): `r g b emissive scale headScale visible`. `headScale` (default 1) grows the parts drawn around the head pivot (`head`, `visor`) about that pivot; 13h multiplies it by `Hitbox.headScale` (X14 Big Head).
- Darkness (`rules.fx.darkness`, X37): `applyTheme` dims sun and ambient light to 5 %, fog and sky go near black, the fog is full at 22 m, the light bake uses no map lights, and the visible living actors nearest the camera carry a flashlight each (3 m ahead along the view, 11 m radius). `updateFlashlights` (07d, render update 55, after `updateLights`) picks them without allocating (`Flashlights.ids/count`) and writes them straight into `Render.frame` lights after the effect lights, never through `Fx.light` slots: one light per actor, no stacking, no fading. They fill the tier's `lights` (at least 1, so the player in the dark is lit even on Low and Potato); muzzle flashes and explosions keep up to 2 of those lights.

## Frame pipeline (internal registries, usable by S07 files)

`Render.addUpdate(order, fn(seconds, alpha))` runs before drawing; `Render.addPass(order, fn(gl))` draws into the scene target; `Render.addFinish(fn(gl))` runs after the canvas holds the frame; `Render.addGpuPart(name, fn(gl))` creates GPU objects at init and again after a context restore; `Render.defineProgram(name, vertex, fragment, attributes)` (throws past 8 programs, REN-003).

Updates: -1 benchmark, 0 camera + view-model read, 2 dynamic resolution, 3 auto step-down, 5 fog, 6 sun shadow matrix, 30 actors + blob shadows, 40 sources, 50 lights + live particle counts, 55 flashlights (darkness), 60 view model. `Render.addPrePass(fn(gl))` runs before the scene target is bound: instance upload of props and actors, the sun shadow map (High/Ultra) and its texture binding. Passes: 10 sky, 20 world, 30 shapes (props, actors, outline shells), 40 blob shadows, 50 decals + particles + tracers, 70 view model (after a depth clear, own FOV). Then the post pass (MSAA resolve, upscale, vignette, FXAA) and, in the Loop `hud` phase, the HUD layers.

Programs (7 of 8): `world`, `shapes` (props, actors, view model, outlines, blob shadows), `shadow` (depth-only sun shadow casters), `particles` (particles, tracers, decals), `sky`, `post`, `hud`. Texture unit 1 is reserved for the sun shadow map.

## Map data read by the renderer

- `map.theme`: a `CAT.themes` id (`foundry ruins station canal overgrowth glacier`), default the first row. Sets the material palette, sky, sun, ambient and fog.
- `map.lights` (optional): `[{ pos: [x, y, z], color: '#rrggbb', radius: 8, intensity: 1 }]`, baked into the world's vertex light with a shadow ray.
- Brush `material`: a `CAT.materials` id (unknown = concrete). Every convex brush is drawn from its planes (box, ramp, and any later convex shape S08 builds planes for).

On `world.load` the renderer builds the static mesh from `Render.worldQuery.brushes`: faces cut on a world-aligned 2-6 m grid, then each cell piece is split exactly by the planes of every brush overlapping it (only the parts no brush covers are kept, so off-grid walls leave no holes; coplanar overlaps are drawn once, by the lower brush index; faces touching face to face are dropped). Vertex light = hemisphere ambient x baked AO + sun (shadow ray) + map lights, with rays walked through the renderer's 8 m brush grid. Everything is merged into one buffer with one draw range per 16 m chunk (frustum-culled; the material is a per-vertex index into a uniform table). Chunks are packed in row order (z, then x), and visible chunks that touch in the index buffer are drawn as one range, so the 300 m island on Potato draws 29 calls a frame in all instead of 93 (PERF-004; `WorldMesh.indexBytes` gives the index size). A coarse 4 m sun-visibility grid shades moving objects. A 200 m map with 400 brushes bakes in about 0.1 s on a desktop CPU. On `match.stop` the mesh is freed.

## Data catalogues (src/03b-data-render.js)

`materials` (pattern, scale, colours, emissive, shine), `themes` (sky, fog, sun, ambient, palette overrides), `teamColors`, `fxKinds`, `decalKinds`, `actorParts` (rigid-part humanoid: pivot, offset, size, hold, tilt, aim, swing, tint, `far` = kept in the far LOD, `distant` = kept past `lodFar`, `head`, `detail`; the format is `ACTOR_PART_SCHEMA`), `viewModels` (parts and pose per weapon class; the default hold is `[0.11, -0.1, 0.3]`, which sidearm, smg, rail and tool use; lmg and power hold `[0.12, -0.12, 0.32]`, sniper `[0.11, -0.11, 0.32]`, launcher `[0.13, -0.11, 0.3]`, heavy `[0.13, -0.13, 0.32]`, melee `[0.13, -0.12, 0.3]`), `MODEL_SCHEMA` (the one static model row format). `gearModels` (03r): see Models. `src/03q-data-models-weapons.js`: `weaponModels` (one row per weapon W01..W46) and `projectileModels` (visible projectiles: rocket, missile, warhead, grenade, contact, mine, stake, arrow, needle, shard, disc, hook, drill, blade; the rest stay glowing spheres), see Models below.

## Models (07c-render-models.js)

Built-in 3D models made of the instanced shapes, nothing downloaded: gear (03r), weapons (03b `viewModels` class rows, 03q) and projectiles (03q) share one row format, one part format, one palette, one LOD rule and one builder. Animated actor bodies are rigs in the `actorParts` format (see Actors); they share the LOD rule (`LOD`, `lodFor` in 07c-render-actors), the palette and the glow and shade constants.
- Row (`MODEL_SCHEMA`, 03b): `{ id, from, drop, scale, recolor, parts, color, accent, glow, pose, spin, tumble, muzzle }`. `muzzle` = `[x, y, z]` where a weapon's shots leave, in model space (null: measured at load as the front end of the foremost silhouette / far parts, twin barrels averaged, `model.muzzle` as a `Float32Array(3)`; see `docs/api/weapons-damage.md`, Muzzle). `from` = a row whose parts come first (same catalogue, or for weapons a `viewModels` class row), minus its part indexes in `drop`, times `scale` (a number or `[x, y, z]`), tints swapped by `recolor` (e.g. `{ white: 'body', body: 'white' }`); then the row's own `parts`. `color` = the row's own body colour (-1 = the caller's); `accent` / `glow` = its accent and glow colours ('' = inherited along `from`, else the default); `pose` = the `viewModels` row for hold / ADS / kick (weapons; default the from row's pose, else the weapon class); `spin` / `tumble` = rad/s about the up axis / end over end (projectiles, only while they fly). No row needs code of its own.
- Part: `{ shape (default box), offset [x, y, z] (centre), size [x, y, z] (full size), rotation [yaw, pitch] (degrees, + pitch tips the front up; [0, -90] points the shape's Y axis forward, size[1] = its length), tint, lod, mirror: true (a second copy at -x), role (a MODEL_ROLES name) }`. Model space in metres: x = right, y = up, z = forward (the muzzle, the flight direction); weapons: origin = the grip; gear: the floating centre (pickups), the body centre (grenades) or the floor point (devices). The pose's `mirror` (-1) turns model space into shape space, where local +X is left (DATA-002).
- `tint`: `body` (the caller's colour, or the row's own `color`), `shade` (body x 0.55), `accent` (the row's accent, else body), `glow` (the row's glow, else body; self-lit 0.7), `shine` (accent, self-lit), or a `MODEL_PALETTE` name: `dark steel metal white black red brass wood bone skin cloth` (plain), `visor` (0.8) and `lamp light cyan flame` (self-lit). Body parts take the caller's glow; palette parts half of it, so details stay readable.
- `lod`: 2 = the silhouette, drawn at every distance (a far held weapon's leading parts); 1 = near and far (default); 0 = near only (small details: sights, rivets, labels). One rule by the camera distance and the quality row, as for actors: under `lodNear` every part, up to `lodFar` the lod >= 1 parts, up to `viewDistance` the lod 2 parts, past it nothing. Presets without `modelDetail` (Potato) draw no lod-0 parts even near (and no actor `detail` parts).
- `Models.compile(rows, bases, lookOf)` checks every part (unknown shape, tint or `from` throws) and returns `{ byId, list }` of compiled models `{ id, count, parts, shapes, tints, data, lodCounts [near, far, distant], colors, pose, spin, tumble, centerZ, top }` (parts sorted silhouette first, so each LOD draws a prefix; `centerZ` = the middle of the forward extent, `top` = the highest point). `bases` = a catalogue `from` may also name; `lookOf(row)` = the defaults `{ color, accent, glow, pose }` (the weapon family colour and its pose row's accent and glow; the projectile colour).
- Drawing: `Models.draw(batch, model, pose)` (LOD by distance, `Models.levelOf(pose)`) or `Models.drawLevel(batch, model, pose, level)`, through `batch.meshFrom` with one reused instance record: no allocation, no float arguments (PERF-006). `pose` = a `makeModelPose()` record `{ x y z yaw pitch scale mirror originY originZ r g b emissive highlight }` (a constructor record, see `ShapeInstance`; keep one per caller): yaw and pitch turn the model about the model point `(0, originY, originZ)` placed at `(x, y, z)`; `highlight` = the ACC-006 outline. `Models.paint(pose, model)` copies the model's default body colour into the pose.
- Part roles (P6, `MODEL_ROLES` in 03b-data-animations: `mag slide bolt pump cyl barrel lid cell string arrow`): the part a reload or action cycle moves. `Models.compile` refuses an unknown role; the compiled model has `roles` (a `Uint8Array`, one code per part). A pose moves the parts of a role through `pose.roleMove` (6 floats per role: x y z in model units, pitch, roll in radians, hide) and draws only one role with `pose.only` (the spare magazine). The slot of role 0 is never written, so a pose with `NO_ROLE_MOVE` draws the model unchanged. `Models.drawLoose(batch, pose, loose)` draws a shape that belongs to no model (the off-hand, a spare box) in the model's frame. `ModelPose` also has `roll` (the whole model turned about its forward axis, radians, + = top to the right seen from behind: one more instance float, read by the shape shader before pitch and yaw) and `glow` (the share of the glow tints' self-light, 0..1).
- Weapons and projectiles: `WeaponModels.byId` (weapon ids and class ids), `.weapon[index]` (a weapon without its own row: its class row), `.projectile[index]` (null = a glowing sphere). Users: the view model (07e: every part, no lod-0 on Potato; scale `VIEWMODEL_SCALE`, mirrored for the W04 left pistol, in the `Render.viewModel` colour); the held weapon (`drawHeldWeapon`: at the actor's `gun` part, 1.3 m per model unit, riding on the forearms, one LOD coarser than its actor, none for distant actors); weapon pickups (12a `drawWeaponPickup`: 1.4, spinning about `centerZ`); projectiles (11b: facing their flight direction from launch, kept while they rest or stick).
- Gear (`CAT.gearModels`, 03r; ids = catalogue codes): every item I01..I17 and powerup PU01..PU20 (12a spins and bobs them), grenades (also the grenade in the local player's first-person hand while cooking or aiming a throw, `Gadgets.drawHeld`), placed and deployed devices (the G13 barrier panel matches its row size; an enemy placed device's glint sits on the model's `top`), and `ammo-<type>` boxes (`light heavy shells cells rockets special`, own colours). The I08 Ammo Box (and royale ammo loot) shows the ammo type of the local player's held weapon (the type it gives first), its own box otherwise; royale armor and heal loot show the vest and their consumable, royale squad beacons the G24 model. 12a compiles `GEAR_MODELS`; 12c/12d draw gadgets through `drawGadgetModel(batch, row, pose)` in the row colour.
- Debug (test files): `__CTK.models.gallery(kind, ...)` is the one model view, for `tools/selftest.mjs --no-selftest --eval "..." --screenshot <png>`. `'weapons' | 'classes' | 'projectiles'` (lod, page): 16 models a page side on, left to right and top to bottom, at LOD `'near' | 'far' | 'distant'`; `'items' | 'powerups' | 'thrown' | 'devices'` or a list of gear ids (yaw, scale): a flat floor with the models in rows of 6 and their ids on the HUD; `'bodies'` (actor model kind, '' = all; yaw; quality id): the body models in a line. `__CTK.renderDemo(theme, weaponId)` shows one weapon's view model.

## Actors, LODs and shadows
- LODs by the quality row: closer than `lodNear` all parts of the actor's body model (10 for the default body, up to 18), animated every frame; up to `lodFar` the 6 `far` parts, walk cycle re-posed every 4th frame; up to `viewDistance` the 4 `distant` parts as a still silhouette; beyond that nothing. Presets with `modelDetail: false` (Potato) skip the near parts marked `detail`. The held weapon model replaces the `gun` part near and far (see Models). Gait: the legs cycle once per `WALK_CYCLE_METRES` (2 x `STRIDE_METRES`, two footsteps), swing and head bob reach full size at `RUN_REFERENCE_SPEED` (7 m/s); all three constants live in `03b-data-movement.js`.
- Body models (`src/03s-data-models-actors.js`, catalogue `actorModels`): one row per look, `{ id, kind: 'default' | 'hero' | 'class' | 'ruleset', name, color, base, drop, change, parts }`. A row starts from `base` (an earlier row) or the `actorParts` body, drops base parts by id, changes base parts by id (`change: { torso: { size: [...] } }`) and adds `parts` in the `actorParts` format (built with `bodyPart(region, shape, offset, size, tint, extra)` / `bodyPair` for mirrored left-right pairs; regions `head chest hips shoulder leg` carry the pivot and pose of the base part they sit on). Row 0 is the default body. Tints `team` and `teamDark` take the team colour, `model`, `modelDark`, `modelGlow` the row colour (heroes: the hero row's colour); any `MODEL_PALETTE` name (`dark steel white cloth red skin visor`...) is fixed; torso and arms keep the team tint, so teams and the colour-blind palettes stay readable. Rows add near parts only (the far LOD keeps the 6 base far parts, REN-002); a far silhouette comes from `change` on base parts (a hero's helmet replacing the head). `tilt` pitches a part's shape without moving its centre (a cylinder with tilt 90 points forward).
- `ActorModels` (07c) resolves every row once at load into `lists[row][LOD.*]` = `[near, far, distant, plain]` (there are no `FAR_PARTS` / `DISTANT_PARTS` lists) (`plain` = near without `detail`); `ActorModels.set(id, kind, modelId)` picks the row an actor wears (unknown = row 0; reset on `actor.create`), and S13 `Economy.applyBodyModel` calls it on spawn: the hero, else the class, else the ruleset's row. Drawing reads `ActorModels.index[id]` and allocates nothing. `drawActorPose(id, pose, seconds)` draws an actor at a given feet position and angles; `drawActor(id, seconds, alpha)` is `drawActorPose` at the interpolated live pose. During a replay `fillActors` draws through `Render.replayPose`. PvE enemies keep their own parts (14h), and the local player's body is never drawn into its own first-person camera.
- Shadows: presets with `shadows: 'sun'` (High, Ultra) render one 1024 x 1024 sun shadow map (48 m square ahead of the camera, texel-snapped) from props and actors; the world and shape shaders sample it, static geometry keeps its baked shadows. Actors inside the map lose their blob shadow; the local player always keeps one (MIS-037). Other presets bind a 1 x 1 map and use blob shadows only.
- Particles and decals take the same distance fog as the world (glows fade out in fog). A pool whose particles are all dead is not drawn; the triangle counter counts live particles.

## Weapon animation (P6, 07g-render-weapon-anim.js)
- Visual only. The renderer reads sim state (the `Render.viewModel` and `Render.actorAction` records) and never writes it: reload times, damage times, recoil and equip times are the sim's, and the last phase of every reload ends at fraction 1.0 = the step the rounds are added (self-test group `anims`). Every phase is a fraction of the reload or melee cycle in progress, so attachments and perks scale it.
- Data (03b-data-animations): `CAT.reloadAnims` R1..R14 (phases `[kind, end fraction]` for a partial and an empty reload, the work pose, the moving part and its role, off-hand points, glow, sound marks for P7, third-person numbers; R5 shell by shell has six cycles) and `CAT.meleeAnims` (maul, maulAlt, tanto, tantoAlt, bulwark, three gun bashes by class: contact pose, follow-through, recovery, wind-up, third-person numbers). `weaponClasses` carry the class default `reloadAnim` / `meleeAnim`, `weapons` rows override them; 03c `linkWeaponAnims` resolves them to `weapon.reloadAnimIndex` (-1 = the weapon never reloads), `meleeAnimIndex` and `meleeAltIndex`.
- First person: `ViewAction.update(state, model, seconds)` (called by 07e `fillViewModel` once per frame) sums the layers in `ViewAction.pose` (x y z m, pitch yaw roll rad), `ViewAction.main` (the role moves) and draws the extras (`drawReloadExtras`: the spare magazine, the off-hand: a hand box and a forearm capsule in a reload, a hand on the haft of a two-handed melee weapon; `drawStriker`). Priority: swap (the swap amount of `poseWeapon`) > reload > melee > block > charge / action cycle > sprint; a higher layer takes the weight of every lower one to 0 over a blend, no layer snaps: reload goes out in 0.1 s under a swap, 0.05 s under a strike, 0.06 s when FIRE ends a shell reload; melee goes out in 0.08 s when a reload takes over (and never comes back) and 0.05 s at its end; block 0.1 in / 0.15 out; sprint 0.15 in / 0.12 out. Reload, melee, sprint and block offsets are weighted by 1 - `ads`. Every offset is 0 in the idle hold pose, so `Muzzle` (11e) and the 2 mm view-model probe are unchanged. The hit knock (a hit on the player: 2 to 4 cm down and 4 degrees pitched down) rides on top.
- Reload work pose: `work` / `keys` of a `reloadAnims` row give where the magazine well (`about`, else `seat`) goes (x y z, view metres from the hold pose) and the pitch (+ = muzzle up), yaw (+ = turn in, to the left) and roll (degrees) of the gun; the gun tilts ABOUT the well (`tiltAboutWell`), so the muzzle rises and turns in while the well, the hands and the spare stay near the lower centre of the screen and the back end drops away from the eye. Self-test `anims` bounds every frame of every reload and strike of all 38 weapons: the view model covers at most 30 % of a 16:9 screen (`ANIM_COVER_MAX_SHARE`, every part box projected into a 64 x 36 grid) and its nearest corner is at least 0.12 m from the eye (`ANIM_COVER_MIN_DISTANCE`; the view-model near plane is 0.01 m). `__CTK.animCover(weaponIds)` prints the worst share and nearest corner per weapon.
- Melee: the contact pose is drawn on the first frame at or after the hit tick (`Weapons.meleeAt`): the swing arc is that one frame. Follow-through and recovery fill `Weapons.meleeCycle` (the cooldown the sim added) and end exactly when the weapon may act again; a hit the player lands holds the contact pose 0.03 s (hit-stop) and the rest runs faster to end on time; a held trigger winds an auto weapon up from 0.8 of the cycle; repeated chops turn and roll the other way (yaw and roll mirror; the position does not, so a backhand starts from the same place on the screen). A quick melee by another owned melee weapon draws it in the left hand and dips the gun in hand.
- Third person: 07c `animateActor` calls `computeActorAction(id, pose, seconds, lod)`; `ActorAction.pitch / y / z` (per slot, slot 0 = 0) are added by `placeActorPart`. A body that is stunned (`ACTOR_FLAG.FROZEN`) staggers (arms down 30 degrees, gun down 20); a hit body flinches (torso and head pitch away from the hit relative to where it faces: melee 12 degrees, heavy blows 18, bullets up to 6, blasts 10; 0.05 s in, 0.25 s out, 0.35 for heavy blows). Near bodies on presets with `modelDetail` also detach the weapon model's moving part (`ActorAction.roleMove`).
- `Render.viewModel` animation fields: `reloadSet`, `reloadEmpty`, `reloadFirst`, `reloadLast` (a shell reload's cycle), `swapping`, `meleeAge` (s since the hit tick, -1 = none), `meleeCycle`, `meleeKind` (1 primary, 2 alt, 3 quick), `meleeStriker`, `meleeAnim`, `meleeHit`, `meleeCount`, `meleeAt`, `weaponIndex`, `fireHeld`, `chargeFraction`, `blocking`, `parry`, `blockPool`, `reflectAge`, `sprinting`, `cycle` (the W19 pump / W24 bolt share of the shot interval, -1 = none).
- Debug: `__CTK.animDemo(weaponId, what, fraction, options)` (`what`: `reload`, `melee`, `sprint`, `block`; options `empty`, `first`, `last`, `ads`, `anim`, `kind`, `striker`, `count`, `parry`, `quality`) puts one frame of an animation on screen for `tools/selftest.mjs --no-selftest --eval "..." --screenshot <png>`.

## Quality control

- Dynamic resolution (PERF-007): scale steps of 0.05 inside the preset's `renderScaleMin..Max`; lowers after 0.5 s over budget, raises after 2 s under 80% (GPU timer: 6 ms budget). Without `EXT_disjoint_timer_query_webgl2` the smoothed frame interval (time constant 0.1 s, the same response at any refresh rate) is compared with `slowFrameMs()` = 1.08 x the 60 fps floor, or the display's own interval when it is slower (`DisplayRate.intervalMs`: a 30 or 50 Hz display is not lowered for frames no setting could make faster; a vsync-locked frame shows no headroom). The display interval is measured from 120 frames that the display paced, in the menu or in a running match: uncapped, no benchmark, in the menu the previous frame drew at most 256 triangles (no world: the map editor draws a whole map in the `menu` state), and its CPU work took under half its interval, and so did its GPU work when the GPU timer exists (a GPU-bound phone held to every second vsync looks exactly like a 30 Hz display); the lower quartile of the samples is taken and kept only when it lies within 4% of a standard refresh rate (24 25 30 48 50 60 72 75 90 100 120 144 165 240 Hz), else the last value stays. Without the GPU timer an interval slower than 60 Hz is kept only when the same rate held while the pixel count at least halved (`DisplayRate.candidateMs` / `candidateScale`, scale squared), or at the preset's minimum scale: a GPU frame time follows the scale, a display's interval does not; 60 Hz or faster is kept at once (it never raises the budget). So a slow editor map, a busy CPU or a GPU-bound menu never raises the budget and never switches off the scale drop or the step-down for the next match. The step-down uses the same limit. A drop within 3 s of a raise makes the scale it dropped to a ceiling: raising above it is retried only after 30 s, and each failed retry doubles that wait (no cap), so a GPU-bound phone settles instead of stuttering. A new preset or screen size forgets the ceiling.
- First-run benchmark (PERF-008): when `video.autoQuality` is empty, the menu draws a 3 s stress scene, syncs each frame with a 1-pixel read and maps the median frame cost to a preset (<= 3 ms ultra, 5 high, 8 medium, 13 low, else potato); emits `toast`.
- Step-down (PERF-013): while playing, under 60 fps for 5 s lowers one preset for this session only, through `Quality.setSession(id)` (`Quality.sessionId`, never saved), and emits `toast` and `quality.change`. `Quality.current()` returns that preset, so the renderer, the audio and the PERF-009 caps (bots, PvE enemies, props, voices, map generator tier) drop together, and after a step-down the particle and decal pools draw at most the new cap. Choosing or benchmarking a preset (`video.quality` / `video.autoQuality` change) ends it; the next launch retries the saved preset. The slow time is held back only while a lower render scale can still help: automatic scale above the preset's minimum and either no GPU timer or the GPU timer over its budget. A CPU-bound device (GPU timer within budget) steps down even at full scale.
- Context loss (PLT-005): `Game.pause('graphics')`, `toast` "Graphics restoring...", everything rebuilt from CPU copies on restore, then a `toast`. Only a running match is paused for the loss, and a restore resumes only that `'graphics'` pause (`Render.pausedForLoss`); `match.stop` clears it, and a match started during the loss is paused with `'graphics'`. If the rebuild throws, the PLT-002 fatal screen is shown instead of a frozen, paused frame. If no restore comes within `Render.restoreWaitMs` (5 s of visible time; a hidden tab does not count), the save is written and the fatal screen "The graphics stopped" shows with a Reload button; a restore after that removes the screen again, leaves the match paused behind the pause menu, and does not resume it.

## Events

Consumes `boot`, `setting` (`video.*`), `quality.change`, `world.load`, `match.stop`. Emits `toast` `{ text }` (benchmark result, step-down, context loss / restore).

## Stats

`Render.stats` = `{ drawCalls, triangles, renderMs, gpuMs, renderScale, particles, instances, droppedInstances }`, copied every frame into `Perf.counters` (`drawCalls triangles renderMs gpuMs renderScale particles`; the HUD phase adds its draw calls and `hudMs`). `Render.gpuMemoryBytes()` estimates GPU memory (PERF-005; tested under 64 MB on High and 32 MB on Potato).

## Debug

`__CTK.renderDemo(themeId, weapon, qualityId)` (test file; `weapon` = a weapon class or a weapon id) fills `Render.worldQuery` if it is empty, loads a sample arena with 8 actors, effects, a player view model and a HUD layer, draws a frame and returns frame stats. `__CTK.renderState()` returns `{ render, worldMesh, hud }`. `__CTK.actorModelGallery(kind, yaw, qualityId)` (20b-test-models-actors) lines up every body model of one kind (`''` = all) in the demo arena in front of a fixed camera (yaw PI faces it, 0 shows the backs) for screenshots: `node tools/selftest.mjs --no-selftest --eval "document.getElementById('overlay').style.display='none'; __CTK.actorModelGallery('hero')" --screenshot heroes.png`.
